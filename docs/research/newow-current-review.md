## 口径审计结论与后续任务

### P1：先补原站证据，再决定公式变更

1. **目标/吸筹**：冻结同标的、周期、采集时刻、当前选项、页面值和真实输入，重点补顺灏股份与周线案例。分别核对 HHV/LLV、周期选择、昨收 clamp、当前/历史截止及 owner；出现差异先定位层次。现有代码的 previous_close_activation、original_page_timing 与 futures_segment 子项缺口不能靠一个截图关闭。
2. **CLEAR 与震荡 60 分钟**：按可见精确 entry/exit 身份对照参考价和收益，核对同 Bar 清仓再建仓、期初未配对 CLEAR、零交易、换月中断。三策略 × 日/周/60 分逐格记录，不借用另一组合结果。前后版本无法取得同输入时，记录“无法判定公式是否变化”。
3. **综合解释**：采集同快照趋势/震荡的周、日、60 分事实与分项评分，建立 R2、错配、已清计龄的输入输出表。先判定纯文案变化还是规则变化；新诊断 token 与计算规则证据不足时保持 EVIDENCE_REQUIRED，不改 active 评分。
4. **UI 修复公告**：金钼股份周线卖出标记须绑定正确 Bar 和选中策略；日期布局至少覆盖同日多笔、跨年和归一期货夜盘。盘中/收盘边界需要不同时间的真实观察，不用改系统时钟冒充。

通过条件：每项都能指出明确原站样本、当前代码对应点和差异类型；缺输入则如实关闭为“证据不足”，不得伪造 golden。本轮不输出新的公式版本或 OOS_PASSED。

### P2：收益分析与嵌套路径的独立设计输入

收益任务必须先明确：简单相加还是复利；OPEN 浮动是否进入曲线；年化按自然日、交易日还是 Bar；回撤基于哪条序列；统计窗口、期初已有、零交易及换月中断如何处理。形成独立 reference_model_version 和只读结果合同后，再决定最小 API 扩展。当前 closed-only 摘要与独立 comparator 均保持原口径。

嵌套任务必须先明确：每周期成本/目标来自哪个信号、物理合约与 segment；周/日/60 分输入的 bar_end/as_of；未完成层如何展示；预测区和止损线是原站公开公式还是归一新研究假设。只允许解释性显示，不转换成仓位、止损订单或隐藏过滤。

这些候选的实现需要后续独立 Plan；本轮交付为问题清单与验收输入，不假称设计口径已经确定。
