## 2. 部署、依赖与写入权

沿用模块化单体，一个仓库。Workspace、Market、Trading 是可分别更新的常驻职责；Research 是按需进程。Market 可复用唯一 MD 连接；Trading 可在不启用 TD 的环境测试。现役快期和苏冰宿主保有自己的生命周期。首版不引入通用调度平台、虚拟子账户、常驻研究集群或新消息中间件。

| 模块 | 输入 → 输出 | 写入权与故障边界 |
|---|---|---|
| Market | RQData 历史 → staging/校验 → Canonical Parquet → Catalog/MainContractMap → MDS；单一盘中源 → completed 输入 | 正式历史沿既有发布工具；Redis 只作缓存，现场缺失原件不能通过历史查询重新签发。 |
| Strategy Core | 已完成输入、规则/参数及显式状态 → 下一状态、主动作、原因和输入引用 | 位于 quant-core。不 import 引擎、Web、DB 或柜台；趋势/震荡及已有融合规则共享，仓位预算属于执行侧。 |
| Research | MDS 冻结输入 + Core → RQAlpha 账户、成交、权益、指标 → PG | 独立环境、串行起步。API 只查已发布 run；框架数据代理必须只读限定输入，不允许隐式网络回源或默认 bundle 替换本地权威。 |
| Trading | completed 与状态 → 新决策 → 风险仲裁 → 意图 → VeighNa → 指定 SimNow 柜台；回报 → 对账 | 柜台是仿真资金、持仓、委托与成交权威；Trading 是该账户唯一执行者。PG 留意图及证据，不维护第二套资金账。 |
| Workspace | PG 已发布研究结果、Market 观察、已核实的账户投影 → PC Web/只读 API | 普通页面请求不下载、不生成回测、不补发、不下单。参数修改产生候选配置，显式激活才改变执行所有权。 |

Web/研究发布不重启 Trading；数据接口变更须证明兼容或受控联合切换。现有发布工具仍按现行 cohort 工作，拆分生效前先验证组件绑定、进程身份及恢复引用，不能直接剪掉启动项。

**供应商口径。** 策略分钟线从物理合约 1m 依同一 Session 生成；例如 10:15–10:30 休市时，米筐直推的 11:00 H1 可能仅含 45 个交易分钟。日线取交易所日行情，周线待完整交易周。接 vnpy_rqdata 时要核对开始/结束标签以及缺值转零。盘后更正生成新的历史版本，盘中首次观察及其缺口按原身份保留。Redis 中仍承担现场原件或恢复引用的内容，须证明有可回读的耐久副本才能按可丢缓存处理。[RQData 通用 API](https://www.ricequant.com/doc/rqdata/python/generic-api) · [VeighNa 数据接口](https://www.vnpy.com/docs/cn/community/info/datafeed.html)

**当时可知与成本。** 显式固定主力规则/rank、交易日和当时可见的横截面。米筐默认 rule=0，FU 正式系列的独立凭证要求 rule=2。手续费、平今费、保证金保存生效日与取得时刻。盘后发布的参数可用于注明口径的结算复算。冻结回测沿用严格后继合法分钟开盘、当前同 Session 限制及成本版本；当前试验一手、零滑点、关闭成交量比例限制，仍校验无量。正式结果只覆盖通过验收的模型。RQAlpha Plus 另属产品，其默认撮合、数据权益和模块不计作开源引擎的能力。[期货数据](https://www.ricequant.com/doc/rqdata/python/futures-mod) · [Plus 配置](https://www.ricequant.com/doc/rqalpha-plus/api/config) · [归一冻结试验](../../../services/newow-rqalpha/README.md)

**账户恢复。** MD 行情、TD 读回和受控模拟报撤分别核验。锁定的网关默认连接 MD 和 TD，TD 登录后自动确认结算；只读验收须能证明实际调用边界。资金、持仓、活动单和当日成交四段读回应绑定同账号、交易日、连接代次、结束标记及回报水位。提交未知保留预留、不重发；重复或晚到回报按原生身份核对。快期文件仅能佐证其记录的事实。[锁定网关](https://github.com/vnpy/vnpy_ctp/blob/fa199f70dac9e242c20e925c17e2241b877e694f/vnpy_ctp/gateway/ctp_gateway.py)

**P6 热路径。** 首查 [quote/receive_completed](../../../services/newow-vnpy/host.py) 与 [TradingStore.transaction](../../../services/newow-vnpy/store.py)。先分别测报价、只观察流、可执行候选及原生回报的排队、锁等待、编解码/摘要、SQL 读写、提交和端到端时间。对照保留现有事务的局部优化与按流隔离状态的改动，选择有测量支持的最小方案。若拆事务，让观察流拥有自己的消费位置与检查点；可执行候选须和对应检查点耐久交接，账户侧按唯一标识去重，预算与意图仍原子提交。恢复时对账，发送前重新核对所有权、可平量与截止。保留同批竞争的确定次序，旧动作过期不重新开仓。

| 故障注入点 | 隔离验证应看到的结果 |
|---|---|
| 完成事件已保存，策略尚未提交 | 从旧检查点消费同一原件，只推进一次；历史修订或断线期间未观察事件不能冒充原件 |
| 候选已提交，账户消费位置尚未前移 | 恢复后幂等领取，同一决策只有一个有效意图及一份预留；过期仅留原因 |
| 下单请求发出，尚无可关联回报 | 保留未知状态与剩余预留，四段读回后按原生身份核实；不能核实则继续阻断新增风险 |
| 成交、撤余单与下一根收线相遇 | 保留决策当时前缀；执行按已核实仓位处理，重复事件不增加成交或多平 |
| 页面刷新、Web 重启或并发单项回测 | 从同一 run 或账户投影读数；已有盘中宿主身份、完成流及回报连续 |

**扩展的验收方式。** 用已有策略与隔离样本证明共享内核可在历史与前向两种宿主给出同一决策，无需另造示范策略。换数据来源只比对标准输入及其来源身份；换账单格式只比原生记录与对账结果。常用看盘软件固定版号、同一物理合约、参数、预热前缀和交易日，先比 OHLCV/OI，再比指标和已收线动作，记录第一处分歧。有原公式来源的策略以来源终端为基准，未取得样本的终端保留未验证状态。

## 3. 合约与时间

以下为领域接口约定。实现优先映射仓库已有类型，仅为缺少的字段加适配。

| 记录 | 最小身份及约束 |
|---|---|
| CompletedInput | 源、物理合约、交易日、周期、Session 段、bar_end、confirmed_at、observed_at、revision、OHLCV/OI、质量状态；时间戳带时区，业务端点用交易所上海时区；历史回放单列 as_of，不能伪造现场 observed_at。 |
| Decision | 规则/参数版本、部署/研究 run、输入身份、决策时点、前状态引用、主动作、原因。Hint、回看重绘、持仓图层、无成交日与未完成输入无执行资格。 |
| ResultSeries / Run | 系列键是策略、品种、周期和已批准的研究配置；不可变的 run 身份另绑定输入清单摘要、主力映射、参数/引擎/撮合/成本版本、初始权益、窗口及截至日。二者分开才能查“这一系列最近成功的结果”。 |
| ExecutionOwner | 模拟环境、账户别名、交易所及品种唯一；值为策略、周期、部署修订。未决委托与旧月仓位同时占用该所有者。账户真名、连接密码不进记录。 |

决策时钟取输入实际可用时点；5/15/30/60m、1d、1w 只在相应周期被证明完成后推进。周中不得使用未来周收盘。聚合以权威 Session 端点为准，尤其是夜盘跨日、短交易段、H1 尾段、午休、节假日。迟到、重复、乱序、累计量回零、无 Tick 尾段与合约更换需显式判定。同一身份同值幂等；同一身份异值隔离该流，暂停新增风险。定时器只可确认已有完整数据，不能造收盘价。

执行时序以一例固定语义：09:05 的 5m 收线，09:05:02 才可用；标为 09:06 结束的 1m 若于 09:05:00 开始，其开盘价已经过去。在严格晚于可用时刻的模型下，该价不可成交；若下一合法开盘为 09:06:00，最早候选为该开盘，再检查交易日、限价、可成交量和成本。历史没有实际接收时间时，用版本化历史可用性假设并披露；不据此断言现场速度。M1 以内的序列不可见，不猜盘中止盈/止损先后。本稿建议首个实验用严格后继可成交分钟开盘；具体撮合/成交量/滑点由 Lane 3 合同批准。报价卡住可停开仓，保护和对账仍继续。

## 4. 研究结果、重跑与发布

1. 固定输入。物理合约序列、当时可知 rank1 和换月、日历、历史有效手续费/平今费、保证金、乘数、最小价位、涨跌停、结算价、手数、初始资金都进入 manifest。首切片可用已标注测试参数，正式结果缺关键字段则不可发布。交易数值出入边界使用 Decimal，原生数值保留可核对的精度及合约舍入。
2. 定义比较。冻结一个开平往返，手工列方向、数量、开/平价、乘数、双边费用、毛/净损益；再测空头、平今、无成交/涨跌停、跨交易日结算和换月。执行域非输入相同的场景，只比较可比状态。隔离账户按 run 计算；单策略结果不可相加冒充共享账户收益。
3. 最小存储。复用可满足合同的表或用隔离新表。Run 记录参数与输入，可见状态、截至日、manifest；Trade 逐笔记录信号、委托、成交时刻与费用；Equity 保存权益、回撤和交易日。成交和曲线均以 run_id 查询。运行状态可为 RUNNING/SUCCEEDED/FAILED。成功发布在一个 PG 事务中校验完整性与系列版本，再切换 published_run_id。失败另记 last_attempt，继续提供旧成功 run，首次失败显示暂无结果。
4. 并发及恢复。对同一系列串行化发布，校验输入代次，旧 run 晚完成不得覆盖新代次。换页游标绑定 run_id 与稳定排序键；同一请求不混两代。任务重试按 run 身份幂等，断点目录先写不可变版本再切指针，悬空目录可回收。先用全量作为正确性基线；任何旧前缀、公式、映射、参数、成本或引擎修订均使相应续跑失效。增量逐笔、费用、权益与全量相同且实测节省时间才采用。
5. 读取与解释。主图标签“历史回测交易”，注明来源、截至日、成本、样本窗口和 run。历史、最新信号、SimNow 事实各自显示。旧零成本参考与账户收益不拼接。截面结果属于样本内研究；OOS、Walk-forward、Shadow 和人工晋升另行交办。点击研究记录可定位物理合约/周期与决策当时的输入引用，后续更正不能改写当时解释。

## 5. 共享仿真账户与配置

默认禁开仓。选定模拟环境、账号身份与读取权限、完成历史预热、风险参数显式批准、交易许可有效、取得账户唯一写入资格且核实柜台实际状态后才接受新决策。用当前配置 revision 比较并交换；启用瞬间再查容量、冲突、未决义务。市场品种上限 70，交易品种含 DRAINING 上限 20，换月旧/新物理合约分别计实际订阅。权限与订阅能力另测。盘中源切换以停旧、记最终水位、核新源、开新代次为序；不让两源推进同一流，也不自动切源补单。

| 状态或事件 | 允许的行为 | 退出依据 |
|---|---|---|
| 启动 / 对账中 | 查账户、持仓、活动委托、当日成交与未决本地意图；先接回报，再建立一致读回，拒绝新风险 | 身份、快照与回报水位一致；读回分段不完整则继续阻断 |
| 可执行 | 对新鲜主动作做账户级串行预算预留；合约级先处理旧单；每个意图先落盘再发 | 成交、部分成交、撤单、拒单均按原生身份更新；终态释放剩余预留 |
| 提交未知 / 断联 | 保留预留与原意图；重连按柜台原生委托/成交身份核对 | 只有可证明的匹配才推进；不能证明时保留阻断与人工处理入口 |
| 退出 / 换月 | 保留旧合约行情、撤单与减仓所需路由；禁止新开；需先核对旧义务再转交所有者 | 旧仓为零、活动单为零、未知意图为零且有新鲜读回；拒绝配置静默强平 |
| 数据缺口 / 风险不可估 | 单品种缺口阻断该品种新增风险；账户不明或未计持仓影响全账户。旧决策过期只记原因 | 重新预热只恢复未来决策；重复成交/读回不产生新动作 |

唯一写入通过账户级互斥与发送前所有权检查实现。持锁进程失联时，接替前证明旧执行者停止且已对账；不能仅凭心跳超时启动第二个执行者。行情及柜台回调不得在耗时研究计算中排队。历史策略和模拟 Core 一致的前提包括初态、输入、成交及账户前缀；不同成交引擎不承诺同盈亏。真实 CTP 和无人值守实盘不在本设计范围。

### 5.1 实施者复核后补定的行为

**动作、仓位和换月。** Core 由合格行情推进信号状态；账户侧由已确认成交推进仓位。HOLD、无入场 CLEAR、重启时历史预热均不生成补开。部分成交 1 手而剩余 1 手仍在途时若出现 CLEAR，先处理尚在途的开仓单，按已核实的实际仓位与可平量产生减仓计划；撤单与晚到成交重新对账，不能按原目标 2 手裸平或反手。切换主力时对新段按现有公式预热，不复制旧仓或把 HOLD 解释成 BUILD。旧月只管理已存在义务；历史 run 必须固定换月/期末持仓政策，期末未平仓按已核实结算价计权益并标注未实现，不伪造成交。未批准跨月处置或结算缺证据时，不发布跨月正式结果。若需强制平仓/移仓，它是需要单独批准的执行模型和费用事件。

**崩溃重放。** 逻辑决策键取环境、账户、部署修订、品种、物理合约、周期、输入身份、动作序号。动作拆腿则按决策键与腿序号生成唯一意图。事务内保存去重键、消费水位、决策及零到多个意图与预留。发送者对意图做持久化单次提交资格领取，再向网关发送。发送前或后崩溃且无法判定外部结果，一律视为未知，宁可暂停核对。收到同一原生回报时按环境、账户、交易日、交易所及经验证作用域内的原生标识去重。只有柜台确认的事实推进仓位；fixture 必测落盘前、领取后、发送后未回执三个断点。

**同时争用资金。** 建议将同一 completed 决策端点的风险增加请求按已部署且当时开市的品种建立有界批次；截止值来自批准的新鲜度预算，预检未配置时禁开仓。只用截止前可用输入，缺口记入批次，不追发迟到请求。撤险/减仓与柜台回报立即处理，不等待开仓批次。风险增加按交易所代码、品种代码、部署身份的确定顺序；这是可重复的默认取舍，不意味着字母靠前的品种更优。仲裁时重新读同一账户的已成交及待成交预算，未确认释放的保证金不提前复用。拒绝写入原因与预算快照，不在随后释放资金时自动重发。相同输入集合倒序到达仍应得到同一获准品种。

## 6. 迁移与撤回

先隔离安装/回放，再跑单品种闭环，然后扩矩阵、接离线账户、验证实际机器，最后按范围切换。新旧读取可短期用于对照，旧价与新价各自署名。切读失败时先停止扩大范围，按已核实的上一发布身份恢复读取；真实账户动作不可用代码回退抵消。旧 Worker 停止前逐一核对首页、API、图表、CLI、定时任务、原始 Event 定位、通知及恢复链。产品经营目标允许退役可再生资产，但实际删除需要精确白名单、依赖扫描、dry-run、可恢复副本/重建证明、一次性执行和读回。Git 历史、正式行情、旧观察原件、独立账户记录与原发布恢复引用受保护。

**验收边界。** 在 M4 16GB/1TB SSD 本机，60/16 与 70/20 两档分别测独跑与一项代表性 RQAlpha 任务同跑。每组至少 100 个热批，含 20 个同步峰值，30–60 分钟代表性回放；同步端点不足时加标注为合成的独立回放。统计可消费输入至策略决策/投影持久化的端到端 p95≤5s、p99≤10s。分报最慢批、账户回报延迟、队列水位、CPU/RSS/swap、SSD、历史读次数与回测耗时。正常热路径不得全历史重算；完整停流后队列能排空，M1 不持续跨下一分钟积压，订单/成交零漏零重。单个指标或 Linux 回放不能替代该机器验收。
