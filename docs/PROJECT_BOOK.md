## 1. 项目定位

归一量化是面向国内期货市场的本地量化研究工作站，用来把数据下载、数据清洗、策略配置、回测验证、回测报告、单笔复盘、信号扫描、模拟交易、风控监控和策略迭代串成一个可持续的研究闭环。

第一版服务 10 万级别中小资金的趋势 / 波段研究，优先覆盖黑色、化工、能源品种。不做公开 SaaS、不做多用户权限、不做手机 App、不做 tick 级高频回测，也不做无人值守实盘。

核心闭环：

```text
数据下载
→ 数据清洗
→ 行情状态识别
→ 策略参数配置
→ 回测验证
→ 回测报告
→ K线买卖点标记
→ 单笔复盘
→ 信号扫描
→ 模拟交易
→ 风控监控
→ 策略迭代
```

## 5. 数据源与统一数据层

数据源不能直接给策略和回测使用，必须先进入统一数据层。

```text
Source Adapter 数据源适配层
  ├── TqSdkAdapter
  ├── RiceQuantAdapter
  ├── TushareAdapter
  └── AkShareAdapter

Raw Zone 原始数据区
→ Normalize Layer 标准化层
→ Quality Check 质量检查层
→ Canonical Store 标准数据仓
```

标准数据仓职责：

- PostgreSQL：元数据、策略、任务、报告、信号、复盘、风控事件。
- Parquet：历史 K 线、tick、大体量行情文件。
- DuckDB：本地研究查询、批量统计、回测读取。
- Redis：任务队列、任务进度、临时状态。

标准 K 线字段至少包括：

| 字段 | 含义 |
|---|---|
| provider | 数据源标识，如 tqsdk、rqdata |
| symbol | 标准合约代码 |
| exchange | 交易所 |
| product | 品种代码 |
| trading_day | 交易日 |
| natural_date | 自然日 |
| datetime | K线结束时间，统一时区 |
| interval | K线周期 |
| open/high/low/close | OHLC |
| volume | 成交量 |
| open_interest | 持仓量 |
| turnover | 成交额 |

关键约束：

- 回测默认读取本地标准化数据，不直接调用外部 SDK。
- 主力连续合约只用于研究展示或合约发现，不直接当成真实可交易合约撮合。
- 没有数据质量报告的数据不能进入默认回测。
- TqSdk、交易账户、API token、Webhook 等凭证只从本地环境变量读取。

## 6. V1 功能范围

第一版必须做：

- 数据中心：数据源配置、合约元数据、历史 K 线下载、Parquet 落地、质量检查。
- K线工作台：K线展示、指标叠加、买卖点 marker、信号解释。
- 策略中心：策略版本、参数模板、适用品种、启停状态。
- 回测中心：逐 bar 回放、手续费、滑点、保证金、交易明细、绩效指标。
- 回测报告：资金曲线、回撤曲线、交易明细、品种贡献。
- 信号扫描：多品种、多周期、信号等级和解释。
- 复盘中心：单笔复盘、错误标签、执行偏差、亏损归因。
- 风控中心：单笔风险、最大回撤、连续亏损、保证金占用统计。

第一版不做：

- 全自动实盘交易。
- tick 级高频回测。
- 复杂盘口队列撮合。
- 多用户权限系统。
- 手机 App。
- 策略商城。
- Web 策略代码编辑器。
- AI 自动生成策略并直接上线。

## 7. 策略与回测原则

初始策略池：

- 苏冰 EMA21 趋势策略。
- 均线突破策略。
- N 字结构策略。

回测默认检查：

1. 是否存在未来函数。
2. 是否存在数据泄露。
3. 是否存在过拟合。
4. 回测成交是否合理。
5. 手续费和滑点是否计入。
6. 保证金占用是否考虑。
7. 单笔风险是否受控。
8. 最大回撤和连续亏损是否统计。
9. 回测结果不等于实盘结果。
10. 实盘前必须先模拟和小资金验证。

## 9. 里程碑

### Phase 0：工作站脚手架

目标：项目结构、协作规范、前后端基础工程、Docker 基础服务和文档体系。

当前状态：基本完成。后端和前端均可运行最小验证。

### Phase 1：数据中心 V0

目标：先用 sample/mock 数据跑通接口和文件规范，再接入 TqSdk/RQData/Tushare 等适配器。

验收：

- 数据源配置只读环境变量。
- 能下载或导入指定期货品种历史 K 线。
- 能写入 Parquet。
- 能写入合约、任务和质量报告元数据。
- 能用 DuckDB 查询本地 Parquet。
- Web 数据中心能展示数据源、任务和质量状态。

### Phase 2：策略与回测 V0

目标：跑通三个初始策略的 bar 级回测。

验收：

- 策略信号无未来函数。
- 回测包含手续费、滑点、保证金。
- 输出交易明细、绩效指标、净值曲线和回撤曲线。
- 报告可保存为 Markdown / JSON。

### Phase 3：Web 研究闭环

目标：通过 Vue 工作台完成 K 线、策略配置、回测报告、信号扫描和复盘。

验收：

- 前端能连接 FastAPI。
- K线图能展示历史行情和标记点。
- 回测报告图表可视化。
- 信号列表和复盘记录可查询。

### Phase 4：模拟与提醒，V1.5

目标：模拟交易、企业微信提醒、人工确认流程。不进入 V1 必做范围。

### Phase 5：半自动实盘辅助，V2

目标：小资金、人工确认、风控拦截后的半自动执行。不做无人值守实盘。

## 12. 项目原则

- 本地优先，第一版不上云。
- 数据先行，先保证数据质量，再谈策略效果。
- 回测必须保守，不能把理想成交当成实盘能力。
- 风控默认开启，任何策略结果都要看回撤和连续亏损。
- 行情、信号、交易、风控拆分，策略不能绕过风控直接下单。
- 第一阶段不做全自动实盘，避免过早放大系统风险。
