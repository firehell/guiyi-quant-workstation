# 归一量化 WorkBuddy 日常命令手册

生成时间：2026-07-09
版本：v1.0
用途：你（用户）在微信 / 企业微信里，把下面任意一节里的「发送文案」直接复制发给 WorkBuddy，即可触发对应工作站流程。
配套文档：`ROLE_SPEC.md`（12 角色）、`TASK_MATRIX.md`（18 类任务出场规则）、`STATE_MACHINE_TICKET.md`（10 状态 + 21 字段任务单）。

---

## 使用总则（每次发送前默念一遍）

1. **所有命令默认只让 WorkBuddy 出"单 / 方案 / 报告 / 评审"，不直接改仓库代码。**
2. 涉及代码动作时，WorkBuddy 只产出 `Codex Plan Prompt` / `Codex Dev Prompt` / `CodeBuddy 执行 Prompt`，由你在 Mac mini 上通过 CodeBuddy / Codex CLI 实际执行。
3. 每条命令都必须最终落到 **测试清单 + 验收标准 + 风险点** 三件套（哪怕还没开发）。
4. 任何「真实写入 / 真实发送 / push / merge / deploy / 改 .env / 删数据」都需你**显式授权**，命令本身不触发。

## 1. 生成任务单命令

**发送文案（复制发给 WorkBuddy）：**

```
@WorkBuddy 生成任务单

我的想法：[用一两段话描述，越具体越好，包括想解决什么、预期效果]

任务类型：[普通功能开发 / 数据模块 / 实时行情监听 / 多周期聚合 / 策略开发 / 策略研究验证 / 企业微信告警 / Dashboard / 回测 / 数据质量检查 / Mac mini 部署 / 其他——见 TASK_MATRIX]

补充信息（可选）：
- 涉及模块：
- 紧急度：高 / 中 / 低
- 已知不做事项：

要求：
1. 按《标准任务单模板》（21 字段）产出 TASK-日期-编号 任务单。
2. 角色：项目经理（编号+状态） + 产品负责人（需求整理）。
3. 只产出任务单，不要开发代码、不要改仓库、不要调用任何代码工具。
4. 必须包含：测试清单、验收标准、风险点（即便尚未开发也要先列）。
5. 标注推荐任务状态（一般为 REQUIREMENT_READY 或 PLAN_READY）。
```

- **任务类型**：由你填写，对应 `TASK_MATRIX` 18 类之一。
- **参与角色（必须）**：项目经理 / 流程调度员、产品负责人。
- **输出格式**：一份标准任务单（Markdown，21 字段齐全），落盘到 `workstation/tasks/`。
- **护栏**：仅产出文档，不碰代码、不碰 Git、不部署。

## 2. 需求澄清命令

**发送文案（复制发给 WorkBuddy）：**

```
@WorkBuddy 需求澄清

背景：[为什么想做这件事，解决什么痛点]

我已想到的点：[列几点，没有就写"暂无"]

要求：
1. 角色：产品负责人主导，项目经理辅助拆分。
2. 输出《需求澄清清单》，包含：
   - 用户场景（谁、在什么情况下用）
   - 阶段边界（V1 做哪一层，明确"不做"）
   - 待我确认的开放问题（逐条列出，我回填后你再生成任务单）
3. 不要开发代码，不要给技术方案细节。
4. 如涉及期货业务规则（交易时段、夜盘、主力切换、手续费、滑点、合约乘数），请量化业务专家一并提示风险点。
```

- **任务类型**：普通功能开发 / 策略研究验证（需求层）。
- **参与角色（必须）**：产品负责人；（可选）量化业务专家、项目经理。
- **输出格式**：需求澄清清单 + 待确认问题列表。
- **护栏**：只澄清需求，不进入方案、不开发。

## 3. 技术方案评审命令

**发送文案（复制发给 WorkBuddy）：**

```
@WorkBuddy 技术方案评审

任务单编号：[TASK-xxxx 或粘贴任务单正文]

重点评审：
- 数据流 / 策略流 / 信号流 / 告警流是否清晰
- 是否适合 Mac mini 本地运行
- 是否符合 V1 不自动交易原则
- 模块边界、接口、测试点是否明确

要求：
1. 角色：量化架构师（主导）+ 后端开发负责人（落地性）。
2. 输出《技术方案评审意见》：通过 / 需修改 / 驳回，并给修改建议。
3. 必须包含：测试清单、验收标准、风险点。
4. 不要开发代码，只产出评审结论与修订后的方案要点。
```

- **任务类型**：普通功能开发 / 数据模块 / 实时行情监听 / 多周期聚合 / 回测模块。
- **参与角色（必须）**：量化架构师、后端开发负责人；（可选）数据工程师、安全与权限专家、DevOps。
- **输出格式**：评审意见（结论 + 修订要点）+ 测试清单 + 验收标准 + 风险点。
- **护栏**：评审不开发；涉及凭证时安全专家一票否决。

## 4. 策略研究评审命令

**发送文案（复制发给 WorkBuddy）：**

```
@WorkBuddy 策略研究评审

策略描述：[策略假设、入场/出场/过滤/止损/止盈逻辑，或粘贴策略 spec]

要求：
1. 角色：策略研究员（主导）+ 量化业务专家（期货规则）。
2. 评审要点：
   - 指标是否重绘 / 未来函数风险（参考 XMA PoC 结论：原始 XMA 不得进正式信号）
   - 信号是否滞后
   - 参数是否过拟合
   - 是否符合期货业务规则（主力切换、夜盘、节假日、合约乘数、手续费、滑点）
3. 输出《策略研究评审建议》：可进入开发 / 需补实验 / 驳回。
4. 必须包含：验证清单、验收标准、风险点。
5. 不要开发代码，只产出研究建议与待验证项。
```

- **任务类型**：策略开发 / 策略研究与验证。
- **参与角色（必须）**：策略研究员、量化业务专家。
- **输出格式**：策略研究评审建议 + 验证清单 + 验收标准 + 风险点。
- **护栏**：纯研究评审，不写策略代码、不回测。

## 8. 安全权限评审命令

**发送文案（复制发给 WorkBuddy）：**

```
@WorkBuddy 安全权限评审

评审对象：[任务单编号 / 涉及模块 / 具体功能描述]

要求：
1. 角色：安全与权限专家（主导，一票否决）。
2. 逐项检查：
   - 是否修改 .env / token / webhook（禁止）
   - 是否删除数据（禁止）
   - 是否自动 push / merge / deploy（禁止）

4. 必须包含：风险点清单、越权护栏确认。
5. 不要开发代码。
```

- **任务类型**：安全权限 / 密钥 / webhook / token 相关任务（任何涉及凭证或自动化执行）。
- **参与角色（必须）**：安全与权限专家（一票否决）；（可选）DevOps、后端开发负责人。
- **输出格式**：安全权限评审（结论 + 红线检查表）+ 风险点。
- **护栏**：安全专家一票否决；任何红线命中直接驳回，不进入开发。

## 通用护栏红线（所有命令共享，无条件生效）

以下动作**任何命令都不得触发**，必须由你显式、单独授权后才可在 Mac mini 上执行：

- ❌ 自动交易 / 自动下单
- ❌ 修改 `.env` / token / webhook / 任何密钥
- ❌ 删除数据（含数据库记录、parquet、日志）
- ❌ 自动 `git push` / `git merge` / `git deploy`
- ❌ 自动部署到任何环境
- ❌ WorkBuddy 直接改写仓库业务代码（只产出单 / 方案 / Prompt / 报告）

WorkBuddy 在标准流程里的唯一写盘范围是：`workstation/` 下的任务单、方案、报告、命令手册等**工作站自身文档**，不触碰 `services/`、`packages/`、`docs/`（项目代码与文档）除非你单独下达文档维护指令。
