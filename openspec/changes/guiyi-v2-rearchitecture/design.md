## 1. 运行时机和所有权

| 用途 | 启动条件 | 消费与写入 |
|---|---|---|
| 行情中心 | 行情到达 | Market 独占同一行情流的写入权，已有订阅继续服务报价、K 线、独立账户等消费者。看报价或收线不会调用牛哇参考公式 |
| 牛哇趋势、震荡、双策略参考 | 交易日盘后增量更新结果通过质量校验并成功发布 | 一个盘后消费者按发布凭证选择受影响的系列，调用现有共享公式；参考动作和研究结果绑定不可变 run。整套参考矩阵不订阅盘中行情、不接风险/账户、不发实时通知 |
| 快期火天大有 | 已启用独立模拟部署的原有输入 | 保留其 60m 信号、1m 行情准入、报价及委托/成交读回和恢复。以原账户合同和原生事实为准。[火天大有合同](../../../docs/HTDY_SIMNOW_V1.md) |
| 苏冰独立量化 | 既有独立共享 Paper 模型的 completed 输入 | 按原有 1m/30m/60m 及同刻顺序消费；原 run、执行事实、模型成交、水位与资金独立。Paper 不连接柜台。[苏冰独立模型](../../../docs/SUBING_DEVELOPMENT_MODEL.md) |

实时准入取决于已启用的模拟部署及其必要输入。只把策略加到研究配置、图表或观察列表，默认进入盘后范围。快期、苏冰和行情展示仍可共用必要的行情原件或已有指标原语；这不会启动牛哇整套参考策略。普通主图观察与账户宿主分别核对注册点。

## 2. 复用与触发

沿用模块化单体和现有进程边界。现役 Market 历史数据依次经过 RQData、staging/质量校验、Canonical Parquet、Catalog/MainContractMap 和 MDS；目标底座及存储选型见 [Market 独立设计](../guiyi-v2-market-foundation/design.md)。盘中报价与盘后权威修订保存各自来源和时间。[现有数据合同](../../../docs/DATA_CENTER.md) · [实时行情](../../../services/quant-api/app/market_data/live_market.py) · [Session 聚合](../../../services/quant-api/app/market_data/aggregation.py)

1. **触发一次。** 以交易日和完整 Canonical 成功发布凭证作为入口，复用 [P4 盘后消费者](../../../services/quant-api/app/services/newow_backtest_eod.py)。任务自动发现/补领成功发布，按受影响品种、策略、周期、输入版本合并。多分片完成前、盘中收线、API 查询、定时钟点本身均不授予计算资格。夜盘按交易所交易日归属。
2. **限定重算。** 数据增量入库后才触发计算。先复用已验证的受影响系列全量回放；只有冻结样本证明等价且有实测收益才采用公式检查点增量。旧日订正须覆盖其预热和后续依赖，周线待完整周。相同凭证跨重启仅发布一次；同日有效新修订单独发布，过期版本不能覆盖新结果。
3. **复用研究内核。** [共享决策入口](../../../packages/quant-core/guiyi_quant/newow/decision_adapter.py) 保留纯计算复用；既有[冻结输入适配器](../../../services/newow-rqalpha/frozen_market.py)属于原 P3/P4 隔离研究实现。研究使用锁定的开源 RQAlpha 6.3.0，目标由独立研究域维护输入及就绪依据，迁移另议。Market 参考任务不负责 RQAlpha 数据，新的 Market 参考策略只声明依赖、预热和版本。
4. **发布与展示。** 沿用[结果存储](../../../services/quant-api/app/services/newow_backtest_results.py)、[查询路由](../../../services/quant-api/app/api/newow_backtests.py)及[现有 Vue 面板](../../../apps/quant-web/src/components/market/detail/newow/NewowBacktestPanel.vue)。按系列原子切换最后成功 run，保留失败尝试。页面分别显示报价时间、牛哇截至交易日及完成时间、试验/正式与更新状态；图上动作定位到原 bar，不能画到最新行情上。模拟各读自己的账户事实。
5. **隔离慢任务。** 研究作业用独立消费与事务，不持有行情或独立账户的写锁，也不共享账户消费水位。盘后批量和下一交易日夜盘可能重叠；按触发来源分别计数，上一交易日成功凭证触发的作业可继续运行。限制后台并发、允许暂停/重试，并用相同输入验证账户消费不受影响。已有 P5 VeighNa 宿主保留为离线资产，本次没有将其设为牛哇或现役账户的新宿主。

**供应商口径。** 策略分钟线从物理合约 1m 依同一 Session 生成；例如 10:15–10:30 休市时，米筐直推的 11:00 H1 可能仅含 45 个交易分钟。日线取交易所日行情，周线待完整交易周。接 vnpy_rqdata 时要核对开始/结束标签以及缺值转零。盘后更正生成新的历史版本，盘中首次观察及其缺口按原身份保留。Redis 中仍承担现场原件或恢复引用的内容，须证明有可回读的耐久副本才能按可丢缓存处理。[RQData 通用 API](https://www.ricequant.com/doc/rqdata/python/generic-api) · [VeighNa 数据接口](https://www.vnpy.com/docs/cn/community/info/datafeed.html)

**当时可知与成本。** 显式固定主力规则/rank、交易日和当时可见的横截面。米筐默认 rule=0，FU 正式系列的独立凭证要求 rule=2。手续费、平今费、保证金保存生效日与取得时刻。盘后发布的参数可用于注明口径的结算复算。冻结回测沿用严格后继合法分钟开盘、当前同 Session 限制及成本版本；当前试验一手、零滑点、关闭成交量比例限制，仍校验无量。正式结果只覆盖通过验收的模型。RQAlpha Plus 另属产品，其默认撮合、数据权益和模块不计作开源引擎的能力。[期货数据](https://www.ricequant.com/doc/rqdata/python/futures-mod) · [Plus 配置](https://www.ricequant.com/doc/rqalpha-plus/api/config) · [归一冻结试验](../../../services/newow-rqalpha/README.md)

**看盘口径与产品范围。** 同花顺期货通、通达信、易星、快期分别记录终端版本、物理合约、交易日、参数与预热前缀。先比交易段端点、OHLCV/OI，再逐根比较指标、动作与首处分歧。按公式来源终端验收，缺样本的终端保留未验证。现役品种清单继续遵守 [product-retirement](../../../openspec/specs/product-retirement/spec.md)；旧容量测试不扩大正式范围。V2 仍按趋势、震荡、融合三个参考系列规划，主升浪独立入口沿原迁移方案核对消费者后退役。

## 3. 合约与时间

以下为领域接口约定。实现优先映射仓库已有类型，仅为缺少的字段加适配。

| 记录 | 最小身份及约束 |
|---|---|
| CompletedInput | 源、物理合约、交易日、周期、Session 段、bar_end、confirmed_at、observed_at、revision、OHLCV/OI、质量状态；时间戳带时区，业务端点用交易所上海时区；历史回放单列 as_of，不能伪造现场 observed_at。 |
| Decision | 规则/参数版本、部署/研究 run、输入身份、决策时点、前状态引用、主动作、原因。Hint、回看重绘、持仓图层、无成交日与未完成输入无执行资格。 |
| ResultSeries / Run | 系列键是策略、品种、周期和已批准的研究配置；不可变的 run 身份另绑定输入清单摘要、主力映射、参数/引擎/撮合/成本版本、初始权益、窗口及截至日。二者分开才能查“这一系列最近成功的结果”。 |

决策时钟取输入实际可用时点；5/15/30/60m、1d、1w 只在相应周期被证明完成后推进。周中不得使用未来周收盘。聚合以权威 Session 端点为准，尤其是夜盘跨日、短交易段、H1 尾段、午休、节假日。迟到、重复、乱序、累计量回零、无 Tick 尾段与合约更换需显式判定。同一身份同值幂等；同一身份异值隔离该输入；账户执行沿各自合同，盘后研究保留旧成功版本。定时器只可确认已有完整数据，不能造收盘价。

执行时序以一例固定语义：09:05 的 5m 收线，09:05:02 才可用；标为 09:06 结束的 1m 若于 09:05:00 开始，其开盘价已经过去。在严格晚于可用时刻的模型下，该价不可成交；若下一合法开盘为 09:06:00，最早候选为该开盘，再检查交易日、限价、可成交量和成本。历史没有实际接收时间时，用版本化历史可用性假设并披露；不据此断言现场速度。M1 以内的序列不可见，不猜盘中止盈/止损先后。本稿建议首个实验用严格后继可成交分钟开盘；具体撮合/成交量/滑点由 Lane 3 合同批准。

## 4. 研究结果、重跑与发布

1. 固定输入。物理合约序列、当时可知 rank1 和换月、日历、历史有效手续费/平今费、保证金、乘数、最小价位、涨跌停、结算价、手数、初始资金都进入 manifest。首切片可用已标注测试参数，正式结果缺关键字段则不可发布。交易数值出入边界使用 Decimal，原生数值保留可核对的精度及合约舍入。
2. 定义比较。冻结一个开平往返，手工列方向、数量、开/平价、乘数、双边费用、毛/净损益；再测空头、平今、无成交/涨跌停、跨交易日结算和换月。执行域非输入相同的场景，只比较可比状态。隔离账户按 run 计算；单策略结果不可相加冒充共享账户收益。
3. 最小存储。复用可满足合同的表或用隔离新表。Run 记录参数与输入，可见状态、截至日、manifest；Trade 逐笔记录信号、委托、成交时刻与费用；Equity 保存权益、回撤和交易日。成交和曲线均以 run_id 查询。运行状态可为 RUNNING/SUCCEEDED/FAILED。成功发布在一个 PG 事务中校验完整性与系列版本，再切换 published_run_id。失败另记 last_attempt，继续提供旧成功 run，首次失败显示暂无结果。
4. 并发及恢复。对同一系列串行化发布，校验输入代次，旧 run 晚完成不得覆盖新代次。换页游标绑定 run_id 与稳定排序键；同一请求不混两代。任务重试按 run 身份幂等，断点目录先写不可变版本再切指针，悬空目录可回收。先用全量作为正确性基线；任何旧前缀、公式、映射、参数、成本或引擎修订均使相应续跑失效。增量逐笔、费用、权益与全量相同且实测节省时间才采用。
5. 读取与解释。主图标签“历史回测交易”，注明来源、截至日、成本、样本窗口和 run。盘后参考、研究成交与两个独立模拟账户事实各自显示。旧零成本参考与账户收益不拼接。截面结果属于样本内研究；OOS、Walk-forward、Shadow 和人工晋升另行交办。点击研究记录可定位物理合约/周期与决策当时的输入引用，后续更正不能改写当时解释。

## 5. 盘中账户保护与迁移

快期保留风险预留、未知提交不重发、未决旧月、撤余单及退出义务，由其原生回报和对账推进。苏冰沿已确认的原件和既有执行事实推进独立 Paper 账本，沿原 run 恢复。盘后参考动作和 RQAlpha 研究成交没有通向任一账户的入口；快期原生记录和苏冰模型成交也不能填补历史研究缺口。

| 故障或操作 | 离线验收应看到什么 |
|---|---|
| 牛哇盘中收到报价、同步收线或页面请求 | 行情仍更新；参考回调、入队、状态提交、意图与通知均为零 |
| 漏接/重复发布凭证，进程提交前后崩溃 | 可从耐久发布事实补领；同一输入版本、同一系列仅一个成功发布，失败可定向重试 |
| 数据迟到、同日修订、分片未齐或旧作业晚完成 | 仅合格且当前的输入可切换成功指针；页游标绑定原 run，未受影响系列零任务 |
| 夜盘进行中，盘后作业重启或 Web 刷新 | 两条模拟宿主身份、水位和账目各自连续；快期无漏重回报，苏冰无漏重模型事件 |
| 旧参考服务与行情/预警/模拟共享依赖 | 明确到路由和消费者；在隔离预览只摘除牛哇参考入口，共享输入照常投递；未查清的切换保留阻断 |

对照 [active 参考合同](../../../openspec/specs/newow-product-reference-trading/spec.md)、[原始观察](../../../openspec/specs/reference-trading/spec.md)、[既有通知](../../../openspec/specs/newow-action-notifications/spec.md)、[苏冰预警](../../../openspec/specs/subing-ths-alert/spec.md)及[首页读面](../../../openspec/specs/market-home-overview/spec.md)逐个列出写入者、读者、消息定位及恢复引用。现役与 V2 的触发方式有差异；先在隔离环境证明不同路径，再提交对应 active delta、切读/停写和回退计划供独立审阅。盘后历史不能重新签发现场观察或补发旧通知。保留旧账户、未结义务、现场原件和恢复依据。生产退役、发布、Runtime 单独批准。

## 7. 隔离切读与现场核对

隔离配置在 Reference Worker 的程序入口停下。其现役计算范围只含牛哇，包含前向订阅与耐久 Inbox、历史刷新、来源对账以及牛哇通知分发。行情的 completed 原件与 Redis 报价、一般 Alert、快期的行情准入和 60m 原始方向、苏冰 Paper 的 completed 消费保持各自入口。历史 Reference API、牛哇消息与原账户账本仍可单独读审计原件。隔离 Web 禁用旧计算型牛哇 GET，使用普通市场行情与盘后结果只读 API。

现场切换前核对正式宿主对 completed 流、前向记录和消息定位的实际依赖、未决账户义务，以及晚到供应商恢复的成功凭证与消费者接续。隔离模式沿既有晚到恢复一次性合同，仅在严格读回通过后留存凭证；处理开始后提交状态未知时，等待更晚的合格发布确认 Canonical。切读回退使用原部署身份和原投影视图，保持旧原件、水位和未决义务。正式环境的停写、配置、柜台、通知或部署另行批准。
