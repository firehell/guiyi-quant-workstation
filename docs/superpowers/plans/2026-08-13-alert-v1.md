# Alert V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Design source：`docs/superpowers/specs/2026-08-13-alert-v1-design.md`  
Design commit：`3bc0030505fb31884396adb173e310c09f50e39a`

**Goal:** 在不改动 Data Foundation 八表、Canonical、rank1 规则和现有 Historical/Live seam 的前提下，新增一个独立、默认关闭的盘中 Alert V1：对 server-side Scope 内品种的 actual-dominant confirmed 15m 使用 Python HTDY original 只检查当前收线 Bar，幂等记录 AlertEvent，发起一次简洁企业微信提醒，并在 Product Workspace 持久显示历史 🔔 Marker。

**Architecture:** 复用现有 `LiveMarketService -> Redis live:bar:*:15m` 作为瞬时触发，`MarketReadService` 负责截至事件 `bar_end` 的 Canonical + Live 统一窗口和当日实际主力 contract context，Python Indicator Kernel 负责 HTDY 权威计算；独立 `AlertRuntime` 只做 Rule/Scope 调度、Event 幂等和 WeCom 一次发送。PostgreSQL 新增 `alert_rules` / `alert_events` 两张 Application Domain 表，Data Foundation / Market Catalog 继续固定八表。

**Tech Stack:** Python 3.13 / FastAPI / SQLAlchemy / PostgreSQL / Redis / Alembic / stdlib HTTP client；`packages/quant-core` Indicator Kernel；Vue 3 / TypeScript / Vite / Naive UI / lightweight-charts；pytest / Ruff / Mypy / Node test runner / Playwright / pnpm。

## Global Constraints

- 事实源优先级：`STATUS.md` -> `AGENTS.md` -> `docs/DEVELOPMENT.md` -> `PROJECT_SOURCE.md` -> `DECISIONS.md` -> 本设计文档。
- Data Foundation Frozen：不得修改 `DatasetKey`、八表 Catalog、Canonical Parquet 语义、月分区模型或 rank1 规则。
- `MarketDataService` 仍是唯一 Historical Gateway；Alert 不得直接读 Parquet、glob 文件或自判主力。
- Historical Canonical 与 Redis Live Observation 继续分离；Alert 不把 Live 写入 Canonical/DB Bar 表。
- V1 唯一真实 Rule 是 `htdy_original_15m`；V1 不建设 Rule DSL、插件平台、多通知渠道、retry、replay、backfill、checkpoint、scheduler 或 Notification Platform。
- HTDY original 继续 `observation_only`、`future_looking=true`、`repainting_risk=known`、`backtest_capable=false`、`live_capable=false`、`auto_order=false`；只开放 `alert_capable=true`。
- HTDY Alert 只接受 `actual_dominant + 15m + confirmed completed bar`，只检查当前最后一根，不扫描历史 repaint 区域。
- Web 现有 `XG观察`、VAR23 / callbackBuy 逻辑必须删除；Alert V1 只使用 Python Kernel 已有 `buy_observation` / `sell_observation`。
- AlertRuntime 离线期间错过的事件永久错过；不补评、不补发。
- WeCom 失败不 retry；数据库不保存 delivery 成功/失败、HTTP status、response body 或 error_code。
- 企微正式消息必须保持短模板，只包含品种、买/卖观察、实际主力合约、15m 收线时间。
- Alert Scope 存 PostgreSQL；现有 browser-local watchlist 不得作为 Runtime truth。
- Persistent Alert Marker 只显示在 `actual_dominant + 15m`，且与 HTDY overlay 开关独立。
- 真实 production migration、真实 WeCom canary、Alert Runtime activation 是三个独立受控外部 Gate；普通代码实现与测试不得执行它们。
- 普通源码实现可按当前 `AGENTS.md` 在 `develop` 完成；每个 Task 结束必须有独立测试结果，失败时不得进入下一 Task。
- 实现验证命令以当时 `TESTING.md` 为准；本计划中的命令是当前 2026-08-13 基线。
