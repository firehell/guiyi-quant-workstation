# AI_WORKFLOW.md — GPT 浏览器讨论到 Codex 工程执行

> 本文定义 GPT-5.5 浏览器聊天、Codex、Browser/Chrome 和用户之间的标准交接流程。目标是把需求讨论、工程执行、页面验收和外部复盘固化为可重复的小步工作流。

---

## 1. 基本原则

归一量化当前第一版闭环围绕：

```text
数据 -> K线 -> 策略 -> 回测 -> 报告 -> 信号 -> 复盘
```

AI 协作必须服务这个闭环，不扩大到无人值守自动实盘、AI 自动下单或没有风控拦截的交易执行。

每轮 Codex 只执行一个边界清晰的任务包。任务包可以是单步小任务，也可以是总控 Prompt 驱动的多步骤计划；任务开始前应先把需求沉淀到 `tasks/current.md` 或 `docs/CODEX_HANDOFF.md`，再由 Codex 读取仓库并执行。

---

## 2. 工具职责

### GPT-5.5 浏览器聊天

适合做：

- 需求澄清。
- 架构讨论。
- 任务拆分。
- 验收标准整理。
- 生成可复制给 Codex 的分步 Prompt。
- 对策略、回测、风控、数据库和数据中心方案做外部审查。

不建议做：

- 直接改仓库文件。
- 直接读取本地凭据或环境变量。
- 直接决定进入实盘或自动下单。

### Codex

负责工程执行：

- 读取当前仓库代码、项目快照、`AGENTS.md`、`docs/CODEX_HANDOFF.md` 和 `tasks/current.md`。
- 按允许修改范围和禁止修改范围小步改动。
- 修改代码或文档后检查 diff。
- 运行测试、构建、静态检查或文档级检查。
- 必要时启动本地服务。
- 对前端页面问题使用 Browser 或 Chrome 复现、调试和验收。

Codex 不应直接读取 ChatGPT 浏览器页面并自动执行。浏览器讨论结果应由用户整理为 Prompt，或写入 `tasks/current.md` / `docs/CODEX_HANDOFF.md` 作为仓库内交接层。

### Browser / Chrome

用于页面级验证：

- 本地 Web 页面复现。
- 控制台错误检查。
- 截图级 smoke 验收。
- K线、回测报告、信号、复盘等页面交互确认。
- 修改前后页面表现对比。

Browser/Chrome 只用于验证和调试页面，不替代仓库文档、测试命令和人工 diff 审核。

### 用户

负责最终决策：

- 确认方向和任务边界。
- 把 GPT 浏览器讨论结果复制为 Codex Prompt，或更新 `tasks/current.md`。
- 审核 Codex diff。
- 决定是否进入下一步、是否提交、是否需要外部审查。
- 管理账号、凭据、密钥和交易相关敏感信息。

## 3. 推荐闭环

```text
GPT-5.5 浏览器讨论需求
-> 生成 Codex Prompt / 更新 tasks/current.md
-> Codex 读取仓库并执行单一任务包
-> Codex 运行测试和检查 diff
-> Browser/Chrome 做页面验收（如涉及前端）
-> 用户审核 diff
-> 必要时把 diff 粘贴回 GPT 做外部审查
-> 用户决定 commit 或进入下一轮任务
```

推荐交接层：

- `tasks/current.md`：当前要 Codex 执行的一轮任务包。
- `docs/CODEX_HANDOFF.md`：账号切换、线程切换和阶段状态交接。
- `docs/CODEX_PROMPT_TEMPLATE.md`：从 GPT 浏览器讨论复制到 Codex 的 Prompt 模板。

---

## 4. 总控 Prompt 模式

总控 Prompt 模式用于减少用户反复复制分步 Prompt 的次数。GPT 浏览器聊天负责把需求讨论、任务拆分、风险边界和验收标准整理成一个总控 Prompt，并同步生成或更新 `tasks/current.md` 里的多步骤任务计划。

推荐分工：

- GPT 负责讨论需求、拆分任务、生成总控 Prompt 和任务计划。
- 用户只需要把总控 Prompt 复制给 Codex 一次。
- Codex 先读取 `tasks/current.md`，再按任务计划从上到下逐步执行。
- Codex 每完成一步必须更新任务状态，记录已完成步骤、测试结果、风险和下一步。
- 低风险文档、小样式、小展示类步骤可以在测试通过后自动继续。
- 高风险 Gate 必须暂停，报告当前状态、拟修改范围、风险判断和需要用户确认的问题。

不建议策略、回测、数据库、风控、数据中心任务无确认全自动执行到底。这类任务即使使用总控 Prompt，也应在关键 Gate 暂停，尤其是涉及策略核心逻辑、撮合、手续费、滑点、`price_tick`、合约乘数、数据库 migration、真实数据或任何实盘边界时。

页面问题可以要求 Codex 使用 Browser 或 Chrome 做验收。验收报告应说明页面地址、操作路径、控制台结果、截图或观察结论。

任何总控 Prompt、任务计划和执行报告都不得写入账号、密码、Token、API Key、交易密钥或其他真实凭据。

## 5. 执行模式

以下任务必须优先 Plan 模式：

- 策略规则和参数变更。
- 回测引擎、撮合、手续费、滑点、保证金、合约乘数相关变更。
- 数据库模型、Alembic migration、数据中心和数据质量口径变更。
- RQ worker、scheduler、异步任务和信号扫描调度变更。
- 风控统计、实盘边界、模拟验证相关变更。

以下任务可以在边界清楚时直接执行：

- 小文档更新。
- 小样式修复。
- 小接口文案或字段展示修复。
- 小测试补充。
- 明确的页面 bug 修复。

页面问题可要求 Codex 使用 `@Browser` 或 `@Chrome` 验收；验收结果应在最终回复中说明页面、操作路径、发现的问题和截图/控制台结论。

---

## 6. 安全边界

任何工具和任何 Prompt 都不得把以下内容写入仓库：

- 账号。
- 密码。
- Token。
- API Key。
- 交易密钥。
- CTP、米筐、天勤等服务的真实凭据。

V1 不做：

- 无人值守自动实盘。
- AI 自动下单。
- 高频交易。
- 信号直接触发实盘委托。
- 没有风控拦截和人工确认的交易执行。

如果 GPT 浏览器聊天中出现敏感内容，交接给 Codex 前必须删除，只保留任务目标、文件范围、约束、验收标准和测试命令。
