## 发现的问题

P1：阻塞主要使用路径；P2：影响判断或交互；P3：展示 / 文档问题。以下把同一原因的相关表现合并，数据可用性问题不直接等同于公式错误。

### 01 · P1 · 首页没有任何可用行情行

- 路径：首页 → 市场 → 全部 / 贵金属 / 黑色系。
- 现场最终状态：`可用 0 / 60，过期 60，缺失 0`，全部品种列表为空；贵金属 `0/4`，黑色系 `0/5`。
- 接口证据：`home-final.json` 中 `status=degraded`、`participant_count=0`、`stale_count=60`、`items=[]`。
- 影响：不能从市场表格进入黄金、焦煤，也不能查看其过期原因或上一交易日行情。与此同时详情页实际可以读取历史和当日分钟数据。
- 需区分：收盘后、盘后入湖前可能存在日线时间差；真正的使用问题是整个首页在这个窗口失去品种行和入口。不能通过伪造新日期或把 stale 改成 fresh 解决。

### 02 · P1 · 首页快照读取耗时达到前端超时边界

- 复现：首次进入市场页显示骨架与刷新中，随后提示“行情快照暂不可用；没有可展示的上一份成功快照”。
- 三次独立只读请求：25 秒超时、40 秒超时，最后一次 23.904 秒才返回降级快照。
- 现役前端 `apps/quant-web/src/api/request.ts` 的超时为 30 秒。
- 影响：不同进入时刻会得到加载失败或空列表；首页不能稳定、快速呈现可审状态。没有把 API 健康探针 200 当成首页可用。

### 03 · P1 · 首页故障蔓延到品种搜索与消息筛选

- 初次在首页搜索黄金显示“目录加载失败，无法安全切换品种”。
- 消息页品种下拉两次检查都只有“全部品种”，无法选择 AU / JM；即使后续首页已有板块数量，仍不能按品种筛选。
- 对照：`/market/dominants` 只读复测 200，耗时 0.39 秒；详情页能够列出并选择黄金、焦煤。
- 影响：行情快照异常时，目录与消息筛选也被拖住。需核对首页 / 消息目录的数据依赖，不能据此认定服务端没有 AU / JM 元数据。

### 04 · P2 · 首次切入牛哇会默认进入未开放日线

- 复现：黄金自由看盘 15m → 点击“震荡策略”。
- 实际 URL 自动变为 `view=newow&strategy=oscillation&frequency=1d`，显示“当前牛哇周期未开放”，还需再点击“切换到已开放周线”。
- 能力接口明确仅开放 `1w`。
- 问题是默认导航落点与已开放能力不匹配；D1 未开放本身不是故障。

### 05 · P1 · 黄金、焦煤牛哇六个当前周线主图均不可用

- 路径：品种详情 → 震荡 / 趋势 / 主升浪 → 1w。
- 页面统一报“主力合约映射缺失（au / jm · 1w）”；同一当前窗口的参考读取也受阻，焦煤比较器同样失败。
- 小写品种的正式查询返回 HTTP 409、`NEWOW_DATA_UNAVAILABLE`、`MAIN_CONTRACT_MAP_MISSING`，标记历史候选可尝试恢复。
- 黄金和焦煤的通用周线行情接口均 200，并不证明牛哇完整输入窗口及 warm-up 具备映射。
- 影响：当前策略状态、主动作、参考交易不能作为已验收页面使用。错误已准确呈现，没有证据表明策略公式计算错误；精确缺口需另做只读数据定位。

### 06 · P1 · 焦煤的历史恢复入口三策略全部失败

- 复现：上述三个策略分别点击“查看最近可用历史快照”。
- 都显示“限定范围内未找到可用历史快照（NEWOW_HISTORICAL_SNAPSHOT_UNAVAILABLE）”。
- 趋势快照接口实测约 14.306 秒后返回 409。黄金相同操作三策略均可恢复到 2026-09-11。
- 影响：焦煤当前页与恢复路径都走不通；不能通过黄金成功来宣布两品种验收通过。
- 限定：报错只证明系统搜索的限定范围内不可恢复，不证明焦煤所有历史日期都没有数据。

### 07 · P1 · 两品种苏冰历史参考交易不可用

- 路径：黄金 / 焦煤 → 苏冰预警 → 乐观参考交易。
- 页面提示“历史参考不可用，请核查数据覆盖或重新读取。实际预警记录独立展示”。
- `/market/au/subing/reference`、`/market/jm/subing/reference` 正式小写请求均 409、`SUBING_REFERENCE_DATA_UNAVAILABLE`。
- 影响：历史重算信号、乐观参考交易和收益区无法核对。已保存实际 Event 仍能独立展示，两者没有被错误混成同一事实。

### 08 · P2 · 点击选择品种后下拉层重新出现，拦截后续点击

- 复现：黄金详情 → 切换品种 → 搜索焦煤 → 点击焦煤选项。
- 品种已切到 JM，但弹层重新列出整个目录；随后点击分析区被覆盖层接收，一度切到了铝。按 Esc、重新选回焦煤后才能继续。
- 代码佐证：`ProductSelector.vue` 的 `choose()` 调用 `close()`；`close()` 在 nextTick 重新 focus 输入框，输入框 `@focus="show"` 又会打开弹层。
- 影响：点击选择与后续操作不连贯，并可能误选其他品种。未将这种控件问题归因为数据故障。

### 09 · P2 · 苏冰“状态不可判定”是固定文案

- 两品种顶部都显示“状态不可判定 · 当前 Scope 已启用 · 最近已评估”。
- 黄金运行展开区同时显示全局 `ok`、Rule 已评估至当日 15:00、错误类型 `—`。
- 代码佐证：`useSubingAlertFacts.ts:56` 在有效 Rule / Scope 分支中直接拼接“状态不可判定”。
- 影响：用户无法分清是 Scope 状态、运行健康还是最近事件状态不可判定。应分别表达事实；本轮没有据此宣称自然通知已送达。

### 10 · P2 · 牛哇价格和收益没有收敛展示精度

- 影响：卡片与标注难以扫描，宽度被长数字占用。这里只需要展示格式收敛，不能借此截断底层计算事实或修改公式。

### 11 · P2 · 趋势主图参考动作标记重叠、贴边裁切

### 12 · P2 · 用户可见的时间与内部标识表达不统一
