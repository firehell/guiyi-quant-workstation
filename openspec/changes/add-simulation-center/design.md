# 模拟交易中心设计

## 职责和复用

MarketDataService 的 completed 数据和物理合约身份进入 Quant Core 与已批准的策略版本。仿真执行层通过原生 VeighNa PortfolioStrategy 或 CTA、MainEngine、OMS、OffsetConverter 与 CtpGateway 接入 SimNow。账户资金、持仓、成交以及结算来自柜台。CTP 报价只服务于执行检查。历史回测、页面参考交易、自研 Paper 和柜台仿真各自保留来源。

P5 共享账户宿主继续作为离线验证资产。新宿主沿用 `services/newow-vnpy` 已验证的 Mac ARM64 依赖、EventEngine、MainEngine 和 CtpGateway。独立部署避免继承 P5 的共享资金与牛哇策略业务。直接维持各旧引擎会保留重复执行入口，自研 CTP 和撮合会重复原生能力。

## 首段读回

每个账户使用独立进程和工作目录。进程通过明确的操作员配置运行，环境限 SimNow，账户别名与经纪商及原生账户身份摘要一对一。配置包含可选的一个策略部署，固定策略目录 ID、公式版本、参数、风险政策及物理合约集合。工作台显示登记与运行证据。首段运行状态为账户观察；策略部署为禁用，切换功能随仿真执行验证交付。

默认 CtpGateway 自动确认结算，且内置轮询只覆盖资金和持仓。只读宿主复用原生 TD 连接、认证和查询接口，覆盖登录结算分支并直接接收四种原生完整查询回报。无 MD 连接。请求按序单飞，记录当前登录代次、交易日、请求编号、终包和回报水位。断线、并发账户变化、回报错误、身份或交易日冲突均使采样失败，保留最后可信样本。持仓、订单、成交空结果只有收到成功终包才有效。连接、结算确认、报撤单是独立的真实动作。

专用 PostgreSQL schema 保存已登记账户、运行状态、完整读回和不可变原生成交。数据库使用独立配置与显式初始化。Web/API 读取只读连接，账户与进程身份冲突时拒绝运行。成交键含账户、交易日、交易所和原生 TradeID，成交关联同日同交易所的 OrderSysID。手续费缺少原生逐笔字段时为空。未发生或未证实的字段保持缺项。业绩按账户展示有时间和来源的权益，在日内以外可有外部资金流时收益率和归因需补齐事实。历史研究结果继续在原领域查询。

## 执行和迁移

交易适配需要 completed 决策原件、出生水位、策略部署身份、稳定意图键及物理合约证据。连接代次变更后必须完成四段对账和未决委托恢复。发送前持久化领取，结果未知时停住并核对原生身份。柜台返回前不制造成交。通用风控优先验证 VeighNa 原生组件；火天大有固定一手和苏冰组合预算按各自已批准合同保留。旧合约仍可保留管理能力直到原生读回无头寸或未决义务。不同独立策略组合优先使用不同 SimNow 账户。

### 离线执行验收

首个执行对象为火天大有。离线运行使用 `offline:<run_id>`，接收归一量化现有 HTDY completed 信号、物理合约和执行输入，复用 HTDY 账户 reducer 的固定一手、反手、风控和恢复。VeighNa OMS 审核同一读回里的订单与今昨仓，通过原生 OffsetConverter 生成请求对象。验收只领取可审计的请求，柜台回包由测试场景明确输入。只有同日、同账户、同原生委托身份的两轮四段读回可以推进对账。

离线命令、状态摘要及请求领取使用专用 PostgreSQL 表，和原生账户读回区分。组合证据包含策略及政策版本、信号原件、费用证据和物理合约。两轮不一致、未知委托、缺逐笔费用或时间证据时保持不能执行。已领取请求无法自动重发。

### 快期退役与 SimNow 新基线

快期停止并归档启动绑定。旧账户的持仓、委托、资金、策略状态和历史继续归旧账户，保留旧账本和最近读回。停用进程不证明旧账户为空，也不触发撤单或清仓。

火天大有从 SimNow 目标账户的新基线启动。首次开通执行前验证原生完整读回、空仓和无未决委托，冻结初始账户和策略启用时间。启动仅接受启用后的新 completed 信号。旧快期历史不进入新账户资金、策略状态或绩效。归档的旧启动配置仅供审计，不作为运行回退目标。正式部署前解除旧快期在运行恢复、保留检查、策略中心、监控 API 与 Web 的现役身份。苏冰共享 Paper 的注册、账本及调度单独评估。
