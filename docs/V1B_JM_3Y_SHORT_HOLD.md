# V1-B — 焦煤 JM 3 年真实数据短持有策略闭环

> 当前阶段单一事实源。V1-B 属于 V1 Web 研究闭环，不属于 V1.5/V2 实盘阶段。

## 1. 阶段定位

V1-B 的目标是用焦煤 JM 最近 3 年真实 RQData / local standard parquet 数据，收敛一条可回测、可入库、可展示、可复盘、可扫描提醒的短持有策略闭环。

旧的 V1-A “焦煤 1 年验收样板”只作为历史参考，不再作为当前目标。后续任务默认以 V1-B 为当前阶段。

V1-B 继续保持主路线：

```text
RQData
→ standard Parquet
→ DuckDB / MarketDataReader
→ vn.py CTA BacktestingEngine
→ PostgreSQL 归档
→ Vue Web 展示
→ K线复盘
→ 信号扫描提醒
```

## 2. 策略范围

本阶段只做焦煤 JM，一个品种，不扩多品种。

核心规则：

1. 日线只用于确定方向，不作为入场周期。
2. 15分钟可以独立入场。
3. 5分钟可以独立入场。
4. 15m 入场后只持有 5-8 根 15m K线。
5. 5m 入场后只持有 5-8 根 5m K线。
6. 行情不利时按止损方法退出。
7. 未触发止损时，按短持有窗口退出。
8. 回测必须计入手续费、滑点、合约乘数、保证金、最大回撤和连续亏损。

严谨性边界：

- 日线方向只能使用已确认日线，不能使用当前未完成日线或未来日线。
- 入场信号不能在当前 bar 直接按当前 bar 成交，必须明确成交时点。
- 5m 和 15m 是两条独立入场链路，不能把一个周期的入场结果混成另一个周期的结果。

## 3. 产品闭环

V1-B 必须跑通：

```text
JM 3 年真实数据
→ 1d / 15m / 5m 标准 K线
→ 日线定方向
→ 15m 独立入场回测
→ 5m 独立入场回测
→ 止损 / 5-8 根 K线时间退出
→ 正式回测报告
→ 回测结果入库
→ Web 资金曲线 / 回撤曲线 / 交易明细
→ K线买卖点 marker
→ 单笔交易复盘 note
→ 信号扫描提醒
```

信号扫描只提醒、解释和记录状态，不自动下单，不创建实盘委托。

## 4. 验收标准

数据验收：

- [ ] JM 最近 3 年真实数据可用。
- [ ] 1d、15m、5m 标准 K线可查询。
- [ ] 数据默认 `data_role=primary`。
- [ ] `quality_status=failed` 的数据不能进入正式回测。
- [ ] 数据来源是 RQData / local standard parquet，不使用天勤旧数据或 legacy 数据做正式回测。

回测验收：

- [ ] 日线方向过滤使用已确认日线。
- [ ] 15m 入场链路可以独立运行。
- [ ] 5m 入场链路可以独立运行。
- [ ] 15m 持仓时长限制为 5-8 根 15m K线。
- [ ] 5m 持仓时长限制为 5-8 根 5m K线。
- [ ] 行情不利时按止损退出。
- [ ] 回测结果能转换为归一量化标准结果。
- [ ] 回测报告、交易明细、资金曲线、回撤曲线写入 PostgreSQL。

Web 验收：

- [ ] Web 能展示 V1-B 回测报告。
- [ ] Web 能展示资金曲线和回撤曲线。
- [ ] Web 能展示交易明细。
- [ ] K线能显示买卖点 marker。
- [ ] 单笔交易能创建复盘 note。

安全验收：

- [ ] 不存在未来函数。
- [ ] 不存在数据泄露。
- [ ] 回测包含手续费和滑点。
- [ ] 回测包含合约乘数和保证金。
- [ ] 回测包含最大回撤和连续亏损。
- [ ] 回测报告明确不等于实盘结果。
- [ ] 信号扫描只提醒，不自动下单。

## 5. 本阶段不做

V1-B 明确不做：

- 多品种批量扩展。
- 参数优化、网格搜索、AI 自动生成策略。
- tick 级高频回测。
- 复杂盘口队列撮合。
- Web 策略代码编辑器。
- Web 大屏扩展。
- 自动实盘。
- 自动下单。
- CTP / TqSdk 交易接口接入。
- 多账户资金管理。
- 云端 SaaS、多用户权限、手机 App。
- 修改 vn.py 源码。
- 提交真实账号、密码、API Key、license、米筐账号、天勤账号、CTP 信息。
