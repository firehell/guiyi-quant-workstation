# v1.3 Release / Runtime / Natural Canary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for this rollout. Do not use subagent parallelism across external Gates. Steps use checkbox (`- [ ]`) syntax for tracking.

Design source: `docs/superpowers/specs/2026-08-14-decision-compression-alert-v2-design.md`  
Prerequisites: `docs/superpowers/plans/2026-08-14-alert-v2-backend-runtime.md` and `docs/superpowers/plans/2026-08-14-decision-compression-web-ui.md` completed and independently reviewed  
Lane: **Lane 3**

**Goal:** 在代码已经完整验证的前提下，以 `v1.3.0` 正式 release，把 destructive Alert V2 schema 和同一 exact tag Runtime 安全切换到本地工作站，保持 SuBing Scope 初始为空；随后在用户明确选择的一个品种上单独开启 SuBing Rule，等待自然 MATCHED 验收 Event、WeCom、首页、Product 今日记录与 exact-frequency Marker。

**Architecture:** 采用本地单用户允许的短维护窗口，不建设 V1/V2 双 schema。先完成 release tag 和独立 runtime worktree 准备，再停止旧 API/Alert 对 V1 schema 的访问；production migration 与 Runtime promotion 是两个独立 Gate。新 Runtime 五个 label 统一绑定同一个 `v1.3.0` peeled commit，读回健康后 SuBing Scope 仍为空。精确 Scope activation 是最后一个独立写入 Gate，成功后才获得该 Rule×Product 后续自然 Signal 的有界持续通知授权。

**Tech Stack / Operations:** Git / annotated tag / git worktree / Python uv / pnpm / Alembic / PostgreSQL / macOS launchd / existing `install-local-services.sh` / local API / Redis health / WeCom Alert Runtime。

## Global Constraints

- 本计划包含真实外部 mutation；**每个标为 Gate 的 Task 在第一次 mutation 前都必须获得用户新的、范围明确的一次性执行意图**。前一步成功不授权后一步，失败重试也要新意图。
- `main`/annotated tag、maintenance service stop、production DB migration、Runtime promotion、SuBing Scope activation 分属不同 Gate。
- 不使用 dry-run、测试通过、旧 v1.2 授权或聊天历史推导真实 mutation 权限。
- 不在 18:05 盘后自动任务关键窗口执行短维护切换；如果当前时间可能覆盖 18:05 触发/一次 1h retry，推迟维护，避免把独立 after-market 自动化混进本次证据。
- Destructive V2 migration 后旧 v1.2 API/Alert 不得继续运行；maintenance stop 必须先发生。
- Live/after-market 不读取 Alert DB schema，可以在短维护期间保持现有运行；最终 Runtime promotion 时仍必须把 API/Web/Live/after-market/Alert 五个应用 label 统一到同一个 exact v1.3.0 worktree。
- migration 前必须只读确认 production 当前 revision 仍是 `20260813_0037`；不是则停止，不猜测兼容路径。
- migration 只修改 Alert Application Domain；八表 Market Catalog 不得改变。
- 新 V2 Rule `subing_entry_signal_v1` 在 migration/readback 后必须 `scope_products=[]`；Runtime promotion 不得自动扩大。
- 不重新执行“真实 WeCom canary”作为发布必要条件；v1.2 已自然验收共享通道，v1.3 通过 mock/renderer 回归和后续自然 SuBing Signal 验收新业务文案。若用户另外要求 canary，属于新的真实通知 Gate。
- Runtime worktree 必须 clean/detached at exact annotated tag peeled commit；不得从 mutable develop 作为最终 Runtime。
- `auto_order=false` 始终成立；任何订单路径出现都立即阻塞。
- 发布/Runtime 完成不代表策略盈利、长期稳定或所有 60 品种适合开启 SuBing。
