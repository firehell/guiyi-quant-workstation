# 归一量化交互视觉规范

生成时间：2026-07-09
版本：v1.1
作者视角：交互视觉专家 / UX UI Designer（见 `ROLE_SPEC.md` 第 9 角色）
配套文档：`ROLE_SPEC.md`、`TASK_MATRIX.md`（交互视觉规范建设任务类型）、`STATE_MACHINE_TICKET.md`、`DAILY_COMMANDS.md`（命令 7/13）、`TEST_EXPERT_HANDBOOK.md`、`STAGE9_WECHAT_DELIVERY.md`（企业微信 payload 字段）
项目硬约束：V1 **不自动交易，仅信号提醒**；国内习惯 **涨红跌绿**；所有对外消息必须明确「观察性质、非交易指令」。

---

## 0. 设计总则与红线

1. **涨红跌绿**：价格/方向维度，多/涨=红，空/跌=绿（国内期货习惯，与美股相反）。
2. **状态色与方向色分离**：状态色（正常/警告/错误…）是「语义色」，方向色（红涨绿跌）是「领域色」。两者出现在不同区域，且**任何颜色都必须配文字标签**，绝不用纯色传达关键信息（防误导）。
3. **处处可见非自动交易声明**：企业微信每条信号/交付消息固定含「仅供观察，不构成交易建议，系统不自动下单」类风险提示。
4. **可读 > 美观**：信息密度高但分区清晰，关键决策字段（方向、价格、状态）一眼可辨。
5. **可追踪**：每条消息/页面带可追溯标识（任务单号、event_id、数据版本、触发时间）。
6. **不制造误导**：不把「已发送提醒」伪装成「已成交」；不把 preview/dry-run 伪装成真实发送。

## 1. 企业微信信号告警模板

> 字段对齐 `STAGE9_WECHAT_DELIVERY.md` payload：`actual_contract`、`continuous_contract`、`bar_end`、`trigger_price`、`quality_status`、`provider/source`、`notice_scope=observation_only`、`trading_instruction=not_trading_instruction`、`auto_order=false`。

### 1.1 Markdown 模板（企业微信 robot markdown）

```markdown
# 📡 信号提醒（仅供观察）

> <font color="#FA5151">多</font> | 品种：<品种> | 周期：<周期>

**合约**：<actual_contract>（主连 <continuous_contract>）
**策略**：<strategy_name>
**触发时间**：<bar_end>
**触发价格**：<trigger_price>
**数据确认**：<quality_status> · 源 <provider/source>

<font color="#FF8F1F">⚠️ 风险提示</font>
本提醒为<font color="#FF8F1F">观察性质</font>，<font color="#FA5151">非交易指令</font>，系统<font color="#FA5151">不自动下单</font>。
```

### 1.2 字段规范

| 字段 | 来源 | 展示要求 |
|---|---|---|
| 品种 | product | 中文名 + 代码 |
| 合约 | actual_contract / continuous_contract | 真实合约在前，主连括注；`actual_contract` 为空或 `*.MAIN` 时**不得发送**（Gate 拦截） |
| 周期 | 策略周期 | 如 15m / 5m |
| 方向 | 多/空 | **多=红(#FA5151)，空=绿(#07C160)**，且必带「多/空」文字 |
| 策略名称 | strategy_name / strategy_code | 完整可读 |
| 触发时间 | bar_end | 交易所时区，标注日期时分 |
| 触发价格 | trigger_price | 来自真实合约 confirmed bar，>0 |
| 数据确认状态 | quality_status | passed/partial/failed；failed 不应进入提醒 |
| 风险提示 | 固定文案 | 观察性质、非交易指令、不自动下单 |

### 1.3 示例（空头信号）

```markdown
# 📡 信号提醒（仅供观察）

> <font color="#07C160">空</font> | 品种：甲醇(MA) | 周期：15m

**合约**：MA2509（主连 MA.MAIN）
**策略**：su_bing_jm_v1b_short_hold
**触发时间**：2026-07-09 14:30
**触发价格**：2523.0
**数据确认**：passed · 源 rqdata

<font color="#FF8F1F">⚠️ 风险提示</font>
本提醒为<font color="#FF8F1F">观察性质</font>，<font color="#FA5151">非交易指令</font>，系统<font color="#FA5151">不自动下单</font>。
```

## 2. 企业微信系统异常告警模板

### 2.1 Markdown 模板

```markdown
# 🔧 系统异常提醒

**异常类型**：<异常类型>
**影响范围**：<影响范围>
**发生时间**：<发生时间>
**当前状态**：<font color="<状态色>"><当前状态></font>
**建议操作**：<建议操作>
**是否需人工处理**：<font color="<状态色>"><是/否></font>

<font color="#FF8F1F">⚠️ 说明</font>
本消息为系统运行状态提醒，不涉及任何交易动作。
```

### 2.2 字段规范

| 字段 | 内容 | 展示要求 |
|---|---|---|
| 异常类型 | 断网/数据源失效/进程崩溃/磁盘/定时任务失败… | 分类标签 |
| 影响范围 | 受影响模块/品种/链路 | 明确边界，不夸大 |
| 发生时间 | 时间戳 | 交易所时区 |
| 当前状态 | 恢复中/已恢复/待处理/已降级 | 配状态色 |
| 建议操作 | 具体可操作步骤 | 可被执行，不含自动动作 |
| 是否需人工处理 | 是/否 | 明确，避免含糊 |

### 2.3 示例

```markdown
# 🔧 系统异常提醒

**异常类型**：RQData 数据源失效
**影响范围**：实时监听链路（不影响已落库历史数据）
**发生时间**：2026-07-09 21:05
**当前状态**：<font color="#FF8F1F">降级运行中</font>
**建议操作**：检查家庭网络与 RQData 授权；系统已自动暂停失效数据写入，恢复后继续。
**是否需人工处理**：<font color="#FF8F1F">否（自动降级）</font>

<font color="#FF8F1F">⚠️ 说明</font>
本消息为系统运行状态提醒，不涉及任何交易动作。
```

## 3. 任务交付报告视觉结构

> 对应 `DAILY_COMMANDS` 命令 13 与 `STATE_MACHINE_TICKET.md` 交付报告。企业微信版精简，文档版完整。

### 3.1 企业微信版（精简）

```markdown
# 📦 交付报告 · TASK-<编号>

**摘要**：<一句话结论>
**完成内容**：<要点列表>
**未完成内容**：<遗留项，无则填「无」>
**测试结果**：<通过率 / 分层结论 / 结论：通过·有条件·不通过>
**风险点**：<关键风险>
**是否建议合并**：<font color="<状态色>">是/否（条件）</font>
**下一步**：<建议方向>

<font color="#FF8F1F">⚠️</font> 本报告仅供 review，merge/deploy 由你手动执行。
```

### 3.2 文档版（完整，落盘交付报告）

| 区块 | 内容 |
|---|---|
| 摘要 | 本次交付一句话结论 |
| 完成内容 | 逐条变更/能力 |
| 未完成内容 | 遗留项 + 标红风险 |
| 测试结果 | 分层执行结果表（见 `TEST_EXPERT_HANDBOOK` §7）+ 验收逐条对照 |
| 风险点 | 未闭环项、技术债 |
| 是否建议合并 | 通过 / 有条件（需先修 X）/ 不通过 |
| 下一步 | 下一阶段方向 |

## 4. Dashboard 信息架构

布局原则：顶部全局状态条 → 七大模块卡片 → 底部最近任务/日志。模块可按角色折叠。

```
┌─────────────────────────────────────────────┐
│ 全局状态条：运行/异常 · 最后更新 · 非自动交易声明 │
├──────────────┬──────────────┬──────────────┤
│ 今日运行状态  │ 数据状态      │ 实时监听状态  │
├──────────────┼──────────────┼──────────────┤
│ 策略状态      │ 告警状态      │ 错误日志      │
├──────────────┴──────────────┴──────────────┤
│ 最近任务（TASK 列表 + 状态）                  │
└─────────────────────────────────────────────┘
```

### 4.1 今日运行状态
- 系统在线/离线、运行时长、最后健康检查时间、进程数。
- 异常时高亮「错误」色并链接到错误日志。

### 4.2 数据状态
- 各周期（1m/5m/15m/30m/1h/日/周）最新更新时间、RQData 同步状态、active Gate 通过数/部分数（参考 Stage 8.6 审计：active_passed/partial）。
- 缺失/重复 bar 计数（来自数据一致性测试）。

### 4.3 实时监听状态
- 监听中品种数、最后 tick 时间、断线告警、聚合产出延迟。

### 4.4 策略状态
- 每个策略：名称、版本、状态（研究中/冻结/历史主线）、最新信号时间、近 N 日信号数。
- 重绘风险策略（如 XMA PoC）明确标「观察专用，不进正式信号」。

### 4.5 告警状态
- 企业微信发送统计：已发/失败/重试中/跳过（skipped，Gate 拦截）。
- 点击查看最近一条 payload（脱敏）。

### 4.6 错误日志
- 时间倒序错误列表，分级（P0/P1/P2），可展开详情；敏感字段已脱敏。

### 4.7 最近任务
- TASK 列表：编号、名称、状态（状态色）、参与角色、最后更新；点击跳任务单。

## 5. 状态颜色和文案规范

### 5.1 状态色（语义色，配文字）

| 状态 | 色值（Dashboard hex） | 企业微信 font color | 文案 | 图标 |
|---|---|---|---|---|
| 正常 | `#07C160`（绿） | `#07C160` | 正常 / 运行中 | ✅ |
| 警告 | `#FF8F1F`（橙） | `#FF8F1F` | 警告 / 降级 / 待观察 | ⚠️ |
| 错误 | `#FA5151`（红） | `#FA5151` | 错误 / 异常 | ❌ |
| 待确认 | `#1485EE`（蓝） | `#1485EE` | 待确认 / 待处理 | ⏳ |
| 已完成 | `#07C160`（绿） | `#07C160` | 已完成 / 已通过 | ✅ |
| 失败 | `#FA5151`（红） | `#FA5151` | 失败 / 未通过 | ❌ |

### 5.2 方向色（领域色，配文字，涨红跌绿）

| 方向 | 色值 | 文案 |
|---|---|---|
| 多 / 涨 | `#FA5151`（红） | 多 / 涨 |
| 空 / 跌 | `#07C160`（绿） | 空 / 跌 |

> **防误导要点**：方向「红」与状态「错误红」同色但语义不同。规则：
> - 方向色只出现在「信号方向」字段，且必带「多/空」文字；
> - 状态色只出现在「状态/结论」字段，且必带状态文字；
> - 同一卡片内若同时出现，用分区/分隔线隔离，禁止用颜色暗示「红=危险」去解读方向。

## 6. 视觉设计原则

1. **可读（Readable）**
   - 字体清晰、对比度达标（WCAG AA）；企业微信消息分段、关键字段加粗；Dashboard 高密度但留白充足。

2. **可判断（Decidable）**
   - 每个决策点都能从视觉直接得到「该不该关注/处理」：状态色 + 文字 + 分级（P0/P1/P2）；信号消息一眼看到方向/价格/确认状态。

3. **可追踪（Traceable）**
   - 消息/页面带可追溯标识：TASK 编号、event_id、数据版本、触发时间、quality_status；错误日志可下钻到根因。

4. **不制造误导（No Misdirection）**
   - 提醒 ≠ 成交：明确「观察性质、非交易指令、不自动下单」；
   - preview/dry-run ≠ sent：未真实发送绝不显示「已发送」；
   - 方向红 ≠ 错误红：见 5.2 防误导要点；
   - 不夸张影响范围，不把「部分」写成「全部」。

5. **明确「非自动交易，仅信号提醒」**
   - 该声明是**强制元素**：企业微信每条信号/系统/交付消息固定出现；Dashboard 全局状态条常驻显示；凡涉及信号展示的页面页脚标注。

## 7. Web V1-B 落地规范（v1.1）

### 7.1 视觉定位

- 采用“克制科技感的桌面研究工作站”，不做纯展示驾驶舱。
- 网格、半透明和发光仅用于全局背景、Header、选中态和关键异常；数据卡片使用实体高对比背景。
- 长时间阅读优先，页面过渡为 120–200ms，并尊重 `prefers-reduced-motion`。

### 7.2 桌面响应式

| 窗口 | 布局规则 |
|---|---|
| `>=1440px` | 220px 展开侧栏；K 线主图 + 300px 右栏 |
| `1200–1439px` | 64px 折叠侧栏；K 线主图 + 280px 右栏 |
| `1024–1199px` | 64px 折叠侧栏；K 线右栏下移；宽表内部滚动 |
| `<1024px` | 不作为 V1-B 正式验收范围，但页面不应崩溃 |

### 7.3 实现契约

- CSS tokens 为页面样式主来源；Naive UI 因内部需计算 rgba，`theme.ts` 必须使用与 tokens 对齐的具体色值。
- Lightweight Charts / ECharts 不直接使用 CSS `var()`，通过 `styles/chartTheme.ts` 解析后传入。
- Header 的“研究工作站 · 不自动下单”是独立安全边界，不与历史 `research_only` schema 字段绑定。
- 生产页面不得复制 mockup 假数据；Dashboard 指标必须来自现有 API 真实字段。
- 本地 SVG 图标必须有按钮文案、tooltip 或 `aria-label`，不新增图标运行依赖。
