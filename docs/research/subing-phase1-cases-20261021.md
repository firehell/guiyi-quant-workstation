## 使用约束

- 常用日线、5m/15m，也会看30m/60m；接受隔夜。
- owner已提供每天可查看的具体时段，保留于私有产物
  `output/subing-phase1-20261021/owner-interview.json`，不将工作作息写入策略或公共配置。
- 可查看时间不是持续盯盘承诺，也不是能及时处理全部分钟信号的证明。
- 账户本金、单笔/日内风险预算、同时持仓数量、手数/保证金约束仍UNKNOWN。
  既有V2参数不自动成为owner未来使用参数。

## 人工案例采集模板

以下是字段模板，空值均为UNKNOWN，不代表已存在真实案例。
第一批建议包含做对、做错、放弃机会、过早退出、持有升级等不同情况；数量不是盈利证明。

| 字段 | 记录要求 |
|---|---|
| case_id / 来源 | 自己的同期记录、事后回忆、原作者截图或模型诊断；分别标注 |
| 品种 / physical_contract / trading_day | 不知道就留UNKNOWN，不根据价格反猜合约 |
| 判断时点 / 当时最新completed Bar | 写时区；未确认Bar另外标preview |
| 大周期背景 | 周期、EMA版本与当时价格位置；缺证据标UNKNOWN |
| 入场 / 放弃 / 持有 / 减仓 / 清仓 | 按发生顺序记录，不能用最终盈亏代替理由 |
| 当前持仓依据周期 | 记录从何周期升级到何周期及当时原因 |
| MACD / 量 / EMA证据 | 原始图或当时行情前缀；未看到原图不填推测值 |
| 决定与实际成交 | 两条记录分开；日期/时间/数量/价格没有证据不补全 |
| 风险计划 | 计划止损、预算与一手可行性；无同期计划注明事后整理 |
| 原始理由 / 后补解释 | 两列分别保留，补写不覆盖原记录 |
| 程序输出 | run_id、结果SHA、decision_id/原数组行；无直接关联不找“最近一个”冒充 |
| 比较结论 | 一致、不同、证据不足；分入场/持有/退出，不只给总分 |
