## 必须暂停的 Gate

### Gate 1：当前策略逻辑审查完成

触发条件：完成当前策略逻辑审查后。

暂停报告必须包含：

- 当前实现与目标规则差异。
- 当前策略是否存在未来函数风险。
- 当前策略是否存在数据泄露风险。
- 当前回测结果是否能复盘到单笔交易。
- 建议修改方向。

### Gate 2：修改策略核心逻辑前

触发条件：准备修改策略核心逻辑、信号生成、成交时点、持仓规则、止损止盈或参数 schema 前。

暂停报告必须包含：

- 将修改的文件。
- 每个文件准备怎么改。
- 未来函数风险判断。
- 数据泄露风险判断。
- 是否影响历史报告或 Web 展示。

### Gate 3：回测结果明显异常

触发条件：回测出现无交易、交易过多、收益异常、最大回撤异常、信号方向明显反、成交价格明显错位、成本明显缺失等情况。

暂停报告必须包含：

- 异常指标。
- 可能原因。
- 是否需要回到策略、数据、撮合或成本口径检查。
- 暂停前已运行的命令和结果。

### Gate 4：涉及数据库 migration

触发条件：需要新增或修改 SQLAlchemy 模型、Alembic migration、报告表、交易明细表、信号表、复盘表字段。

暂停报告必须包含：

- 需要变更的表和字段。
- 兼容性风险。
- 迁移与回滚方案。
- 是否影响已有报告和 Web 查询。

### Gate 5：涉及数据聚合、撮合、成本或交易参数

触发条件：涉及数据聚合、周期合成、成交撮合、手续费、滑点、`price_tick`、合约乘数、保证金率、主力映射或复权因子。

暂停报告必须包含：

- 具体口径变化。
- 对历史回测可比性的影响。
- 是否需要重新生成报告。
- 未来函数、数据泄露和成交错位风险判断。

### Gate 6：涉及实盘、自动下单、账户或凭据

触发条件：任何内容涉及实盘、自动下单、账户、API Key、Token、交易密码、CTP、米筐或天勤真实凭据。

暂停报告必须包含：

- 触发原因。
- 已确认不会写入仓库的敏感内容类型。
- 是否应终止本轮任务。
- 等待用户确认前不得继续。

## 测试命令

```bash
git status --short
uv run --project services/quant-api pytest -q
uv run --project services/quant-api ruff check .
cd apps/quant-web && pnpm build
```

如本轮只改策略后端，可说明不运行前端 build 的原因；如涉及 Web 报告或 K线 marker，必须补充前端构建或 Browser/Chrome 验收。

## 回测验收标准

- 使用 `data_role=primary` 且 `quality_status != failed` 的 RQData / local standard parquet 数据。
- 回测真实调用 vn.py / VeighNa CTA BacktestingEngine，不使用 mock 或 prepared-only 结果作为正式验收。
- 交易数、收益、最大回撤、最大连续亏损、手续费、滑点、保证金、合约乘数、`price_tick` 字段可解释。
- 每笔交易可以追溯到 K线、信号、成交、报告和复盘入口。
- 回测结果不被描述为实盘收益承诺。

## Web 验收标准

- 回测报告可在 Web 打开。
- 交易明细可查看。
- 资金曲线和回撤曲线可渲染。
- K线上显示买卖点 marker。
- 单笔交易可以创建或查看复盘 note。
- 信号扫描只提醒，不自动下单。
- 页面无明显控制台错误；如使用 Browser/Chrome，应记录页面地址、操作路径和观察结论。

## 回滚方案

- 使用 `git diff` 审查本轮改动。
- 若修改未提交，可由用户或 Cursor 按文件撤销本轮改动。
- 若已提交，可用新提交反向修复，不直接要求 `git reset --hard`。
- 若已生成回测报告，先标记为本轮实验结果，不覆盖历史正式报告。
- 若涉及数据库 migration，必须在 Gate 4 确认迁移和回滚方案后再执行。
