# v1.14.16 — Weekly audit 正式定时启动映射修正

正式 `weekly-audit` 服务曾把 label 中的服务名直接当启动参数，进入手动 audit 入口。手动入口绕过 scheduled 的本周 attempt 去重，小时触发可重复扫描并持有 Canonical 维护锁，阻塞 Reference worker。

本补丁在唯一参数身份入口 `authorized_program_arguments` 中将正式 weekly-audit 映射至 `weekly-audit-scheduled`；首次拓扑安装和定时服务升级 writer 同时复用此入口。严格现场身份校验仍要求精确匹配，不接受旧手动参数作为兼容身份。候选预热参数、其他定时服务、业务公式、Scope、通知规则与消费进度不变。

专用回归覆盖正式参数映射、候选身份、两处真实 plist writer 和隔离 launcher 实际执行路径。工程提交不等于生产服务已切换；本补丁不执行 migration、输入初始化、生产服务操作或通知。

验证：8项专用分派测试；绑定、安装、定时交接与身份回归89 passed、1 skipped（隔离Redis未启用）；另有 runtime entry、weekly audit 与维护所有权回归54 passed；三个修改源文件Mypy与Ruff、secret scan 0 findings、diff检查通过。

参数身份与两个writer位于launcher合同指纹内，此变化不能走混合版本交接。生产切换须在全部旧运行进程退出、所有权释放后冻结旧绑定与精确候选合同；共享dispatcher字节须保持一致，除已独立验证的input变更和本次三文件launcher差异外，DB、Live、formula、reference合同必须相等。不得放宽旧手动参数身份或普遍允许launcher合同变化。
