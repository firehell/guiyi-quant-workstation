# Backtest Center

## Purpose

为归一量化工作站提供可追溯的本机期货历史研究、逐笔回放、实验比较和增量续跑。每次运行固化输入和策略身份，由可复算的原生成交与结算支持研究结论。

## Requirements

### Requirement: Plus 执行与原生数据就绪

回测中心 SHALL 通过已核验的 RQAlpha Plus 原生数据和执行接口运行历史账户。每次启动前应验证引擎身份、授权、所选物理合约、预热与执行窗口、周期、历史交易参数及数据修订。中心不得下载、镜像行情或从 MDS、Canonical、Redis 及 Paper 补缺。

#### Scenario: Market 离线且 Plus 本地输入完整

- **WHEN** 用户提交已具资格的策略与完整的 Plus 数据窗口
- **THEN** 中心只使用该版本 Plus 和所选本地数据完成执行，记录独立输入身份，Market 可用性和盘后凭证均不参与派工。

#### Scenario: 日线齐全但缺执行分钟或 Plus 不可用

- **WHEN** 所选窗口缺分钟数据、引擎仅为开源版、授权不可验证或必要接口不可用
- **THEN** 中心说明具体缺项，不换引擎、不缩短区间、不启动替代回测。已有成功 Run 可继续读取。

### Requirement: 策略接入资格按版本与组合确定

中心 SHALL 引用只读策略目录与所属领域版本，按策略、Profile、品种、信号与执行周期核验资格。适配器复用已有公式并保留数据来源。未经核验的组合明确说明原因。

#### Scenario: 从六策略目录选择策略

- **WHEN** 用户进入配置
- **THEN** 牛哇趋势优先展示已验证组合，震荡、主升浪、双策略分别检验公式和执行政策；双策略保留其两个输入身份。HTDY 标记回看重绘，苏冰提供原回放/Paper 入口，两者均不能从此发起普通因果回测。

#### Scenario: 读取旧 P3/P4 结果

- **WHEN** 用户查询既有牛哇试验
- **THEN** 原 run_id、TRIAL/正式资格、引擎、MDS 输入和读面维持原语义；旧试验不能授予 Plus 资格或写入新结果系列。

### Requirement: 历史成交具备因果时序和物理合约证据

历史执行 SHALL 只接纳已完成且当时可知的策略输入，信号可用后方可按版本化政策提交委托，建模成交不得早于严格后继的合法执行时点。只有引擎确认的成交计入结果。逐笔和结算保留引擎原值、独立时间身份和 Decimal 对账口径。研究成交不得进入模拟或真实账户。

#### Scenario: 收线后才获得信号

- **WHEN** 5m 信号于 09:05:02 可用，09:06 是同 Session 下一合法开盘
- **THEN** 最早建模成交为 09:06。以 P1 冻结样本为对照，其原生委托回调标记为 09:06，原生成交回调标记为 09:07，三项分别保存。涨跌停或零成交量导致无资格时按既定有效期处理。

#### Scenario: 映射、换月或费用核对失败

- **WHEN** 按主力选约却缺当时可知的映射，或旧月带仓而无换月政策，或手续费/结算无法解释
- **THEN** 记录缺失证明、换月中断或对账差异，禁止发布正式绩效；按物理合约区分未平仓估值与平仓成交。

#### Scenario: 换月后首个策略状态为 HOLD

- **WHEN** 策略切换至新的物理合约段
- **THEN** 新段独立预热，HOLD 单独出现不产生开仓委托；旧月持仓与估值始终绑定旧月。

### Requirement: 模板与不可变 Run 快照

中心 SHALL 允许保存模板，并为每次执行固化可追溯的有效配置、数据指纹、引擎及代码版本。原生高级参数限于核验的历史研究配置。

#### Scenario: 更新模板后复查旧结果

- **WHEN** 用户改变模板中的参数、区间或成本
- **THEN** 旧 Run 仍可查看提交时已解析的参数与版本。显式重跑指向来源 Run；原修订不可得时报告不可复算，不用新数据冒充原输入。

### Requirement: 执行、取消、重跑与原子发布

中心 SHALL 持久化 Run 状态，提供启动、进度、脱敏日志、取消、失败原因与显式重跑。同一请求幂等，一个 Run 的终态只能提交一次，发布结果可按原 Run 一致读取。

#### Scenario: 重复点击和主动重跑

- **WHEN** 同一次提交被重送，随后用户明确选择重跑
- **THEN** 重送返回原 run_id，最多启动一次；重跑产生关联的新 run_id，保留两次尝试。

#### Scenario: 取消与发布并发或进程在提交时退出

- **WHEN** 读取方查询任务或恢复器准备重启任务
- **THEN** 按持久化身份核对唯一终态，提交未知先独立读回；成功可读完整结果，已取消不发布，较旧完成与失败不覆盖较新成功结果。

### Requirement: 工作台、分析与逐笔回放

工作台 SHALL 提供按策略、品种、周期、日期和状态筛选的历史及任务计数，显示近期回测、实验与验证。每个 Run 的概览、权益、逐笔、风险和报告须标明来源、样本、费用和指标定义，缺失值须带原因。

#### Scenario: 用户在新结果到达后继续翻页

- **WHEN** 用户已打开 A 的资金曲线和逐笔，B 随后成功
- **THEN** 查询和报告继续绑定 A，刷新与翻页均不启动引擎。用户可分别查看最后一次尝试和最近成功结果。

#### Scenario: 用户点击交易记录

- **WHEN** 选择某 Run 的已平或未平交易
- **THEN** 使用 Quant Chart 定位同修订、同合约和周期的图窗，显示关联信号、实际进出场和持仓区间；未平仓保留未实现估值，图窗无可靠来源时只显示可核验明细。

### Requirement: 实验对比与样本外证据

中心 SHALL 组织参数、策略、品种、周期与成本敏感性比较，固定比较条件并保留每个成员身份、缺失与失败。OOS 与 Walk-forward 必须保留事前切分和选择规则，结果只作为历史研究证据。

#### Scenario: 无已核实的原生优化接口

- **WHEN** 发起多组参数或成本实验
- **THEN** 中心按固定预算拆分独立 Run，按成员报告风险、收益、稳定性与覆盖，未经控制的条件差异阻止同口径排名。

#### Scenario: 滚动验证并审阅候选

- **WHEN** 研究者查看每折训练选参、随后测试的结果
- **THEN** 只用当折训练信息选参，预热不计绩效，合并样本外结果不重复计时；缺折显式标注。候选可引用证据，active 版本、Paper、Shadow 与真实账户均不因该结果自动变化。

#### Scenario: 训练末笔交易在测试窗口才平仓

- **WHEN** 研究者在选参截止时仍持有该合约，且平仓收益在下一测试段才可知
- **THEN** 训练只采用事前约定的边界估值或剔除政策，并记录测试期初状态。改变测试期平仓价不能改变已选参数。

### Requirement: 已结算历史 Run 的原生增量续跑

中心 SHALL 允许用户为具有已认证检查点的成功历史 Run 指定更晚的结束日。新 Run 复用
同一物理合约、有效配置和已验证历史前缀，并从下一交易日的首个 Session 起仅执行
新增行情。结果、结束检查点、来源和实际执行范围原子发布，源 Run 保持不可变。

#### Scenario: 日结时持有物理合约

- **WHEN** 用户从带仓结算边界延长历史 Run
- **THEN** 原生账户与策略从旧结算继续。夜盘首个 Session 前恢复原合约估值，
  同窗全量与续跑的成交时钟、费用、权益和原生日收益一致。进程本地生成的
  原生回调标识仍按其原值归档，已继承的前缀证据与来源 Run 一致。

#### Scenario: 历史数据修订、检查点损坏或重复提交

- **WHEN** 继续执行所需的历史行情、时段、成本、合约证据或检查点不能验证
- **THEN** 返回具体诊断，不派工或发布替代结果。对相同增量请求的重复提交
  返回原子 Run 身份。原 Run 和已发布结果继续可读。

#### Scenario: 旧合约到期时仍有持仓

- **WHEN** 物理合约到期且没有经验证的持仓换月政策
- **THEN** 在原生交割平仓前中断并保留原合约估值。任务详情区分该估值和成交，
  不发布绩效、逐笔结果或续跑检查点。新月另行预热，单独的 HOLD 不发出开仓委托。
