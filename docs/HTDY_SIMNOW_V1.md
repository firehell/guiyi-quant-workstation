# 火天大有60分钟固定一手执行规则

Owner 已确认本规则。当前交付是离线纯状态机和显式输入适配器，不是 SimNow 接入或策略启用；
`auto_order=false`，新版账户政策及本地持久化已实现；没有报单 transport、CLI、API、后台任务或生产账本写入。
现有公式、Alert first-seen、参考模型和收益保持不变。未来连接账号与持续运行分别验收。

## 身份与输入

- 执行政策：`htdy_60m_fixed1_signal_reverse_v1`；公式 lineage：`huotian_dayou_original_v0`。
- 一个专用账号，品种仅来自既有 operational loader，启动时冻结集合。每品种净仓位为 -1/0/+1 手；
  多品种可同时持有，但本规则不定义账户总保证金、最大持仓数或板块上限。
- 复用 `HtdyOriginalEvaluator` 和权威 `MarketReadService.validate_alert_window`；精确32根完成60m窗口，
  signal 保存来源身份、input hash、物理合约、前一端点、Bar结束和首次观察时间。
  输入端点、Session和rank1仍由现有数据域证明，不新增行情resolver。合法跨owner的指标窗口沿用现有合同。
- 显式 seam 只接受原生最新完成观察；不可用历史重算、恢复回填、通知是否成功或图表marker代替。
  生产调度与观察原件绑定尚未接入，调用者必须保留原观察身份和实际接收时刻。
- 原公式会重绘。已冻结的同品种同Bar不因后续方向、输入修订而再开仓；同一来源ID关联不同端点拒绝。

## 交易规则

首次启用要求账号空仓且无未完成委托，只接受启用后新完成Bar。空仓遇buy开多一手，遇sell开空一手；
同向不加仓，无信号持有，可跨日/夜盘。不设价格止损、止盈、持仓时长退出或每日强制清仓，不继承旧Paper日亏规则。
同时buy/sell记录冲突，不新开或反手，并撤销尚未成交的开仓意图；不因此清算已有仓位。

反向先平旧仓，实际平仓Fill确认后才允许反向开一手；等待平仓期间的新合格信号覆盖旧目标。
未决开仓、取消等待和成交回报缺失都占用容量。订单提案必须严格晚于信号实际可用时间；
成交时间必须严格晚于订单创建时间。休市不制造成交，已正常收到的信号可以等下一可交易时点。
本版没有固定分钟数过期参数。

## 故障、恢复与换月

断线或checkpoint恢复后先进入 `RECOVERY_REQUIRED`，核对同一账号的资金、持仓、订单和成交。
`readback_valid=false` 时连撤单提案也不产生；只有完成原生回读才允许执行动作。
未解释外部仓位/委托进入BLOCKED；未知订单、成交状态但缺少逐笔Fill、拒单均停止账户新动作，
不推断失败、不自动重发。只有已完成原生回报核对和完整输入证明后才恢复。

取消义务独立保存为 `cancel_required`，不会被后续同向信号覆盖。取消/拒绝回报本身不释放容量；
`AccountSnapshot.settled_order_ids` 必须由未来adapter在原生订单、逐笔成交和持仓完整核对后提供，
没有该证明保持待恢复。即使核对后仍出现矛盾的迟到Fill，也保存真实回报并取消其他未决开仓；
不能投影到一手模型的真实Fill单列 `unresolved_fill_ids` 并保持BLOCKED，重启不清除该阻断。
首启已核对的历史终态订单保存为baseline，后续原样读回合法；新的未知外部订单仍阻断。

恢复不补开旧信号：未完成开仓先取消，空仓等恢复后的新Bar信号；已有仓位与最新完整方向相反则只平仓，
随后等待新信号。相同方向的已有仓位接管持有，不因重启自行清仓。挂起旧平仓不变成恢复后的补开。
缺完整输入的品种单列阻断，其他已验证品种可以继续；不能证明离线方向时不猜测或补造。

权威主力owner变化时，取消旧开仓，按旧合约持仓创建平仓意图；晚到的旧开仓Fill也必须如实计入并平旧仓。
未成交时仍持有旧仓，不能用新合约价格结算。平仓后等待后续新信号，不搬仓，不消费切换期间的旧目标。
新合约数据不合格不得新开。

## 接口与后续边界

`guiyi_quant.htdy_execution` 提供 `start/apply/checkpoint/restore`；状态不可变，`Transition.effects`
只有SUBMIT/CANCEL提案，不调用Broker。`Fill`保存原生trade/order/account身份、实际价格、费用、成交和记录时间，
不计算或虚构模型PnL；持仓按逐笔Fill重放验证。命令ID+payload hash、trade ID和冻结Bar去重，冲突失败。
Audit保存命令内容、原因和目标/订单状态；checkpoint绑定政策/公式/hash，恢复永远要求账户readback。
hash用于损坏检测，不声称防御有权改写全部内容的操作者。

`app.htdy_execution` 提供 `start_operational` 和 `signal_from_window`，不挂接现有Alert、API或Runtime。
外部调用方负责证明最新原件、owner切换、恢复输入、账户快照和交易Session；不能把任意布尔值当生产验收。
`Advance.opening_allowed`与funding来源是显式资金准入输入，不是已实现账户风控；不满足则不创建开仓提案。
`CLOSE`为语义平仓意图，未来transport必须按原生持仓区分平今/平昨；本次不冒充该适配已完成。

真实发送之前仍需Broker adapter、生产事实绑定、行情准入、原生对账与独立运行验收。下节新版提供本地原子提交及账户风控，不可直接连接旧版入口。
不得直接把内存effects循环接到下单API；本模块没有可开启自动交易的入口。

## 闭市旧日来源差异的输入诊断

准入诊断版本 `htdy_60m_input_admission_v2` 将“旧日差异未解释”与“已核验差异、等待新交易日”分开。
只有权威完整交易日已结束、Canonical最新32根预热及底层1m验证通过、同合约原件完整、两套1m各自
聚合与各自60m一致，且具体字段差异和物理来源hash可核验时，才可记为
`CLOSED_SOURCE_REVISION_WAIT_NEW_OBSERVATION`。该证据只证明已存两份事实不同，不反推RQData修订原因或发生时间。

诊断还必须证明下一Session属于严格更晚交易日、rank1及首个H1端点已由Calendar/Session确定；
覆盖该未来边界的恢复围栏、原件变化、身份/质量/可选值未知或缺口均继续阻断。
下一合约预热及真实新输入仍按原生路径重新检查，日程证明不代表未来Bar存在。

原始Live、旧信号、持仓及既有中断保持；旧日 `bars_until` 冲突仍拒绝，`calculation_input` 和
原始Live状态不改成通过。新分类不返回可执行窗口，`first_seen_proven=false`、`eligible_now=false`；
只允许等待新交易日的自然completed输入，再执行统一新鲜度、完整性、owner和恢复检查。
不能用本诊断结果绕过执行政策或启用自动交易。盘中/午休/未完成交易日不得套用此闭市分类。

## 账户风控与报单决策（2026-10-25确认）

本节规则由独立离线账户政策 `htdy_60m_account_execution_v2` 实现，只读CLI不执行订单。
风险身份为 `htdy_simnow_margin70_skip_v1`，报价执行身份为 `htdy_simnow_opponent_reprice180_v1`；
两者独立于原公式、参考收益和既有执行政策，不启用Runtime或订单。

- 保证金上限按实时账户权益70%控制；同一品种最多一手，不另外限制总持仓数或板块。
  额度核算须含原生持仓占用、冻结保证金及尚未体现在柜台的本地开仓预留，去重后计入本单预计新增保证金。
  开仓还须可用资金充足、元数据/保证金事实有效；预计超过上限则拒绝本次开仓。
- 按信号首次实际可用先后处理；同一时刻采用固定品种顺序确保重放一致。
  较早信号被资金拒绝不阻塞后面的新信号判断，不建立资金释放后的历史信号补单队列。
- Owner明确选择A：**资金不足或额度拒绝的本次开仓信号彻底跳过**，保留信号及拒绝原因，
  资金释放也不重试；重复处理相同信号/同Bar不重新获得资格。只有后续新的合格信号才可再申请开仓。
  例如某信号被拒绝，随后资金释放但没有新信号，则仍不建仓。
- 额度只约束新开仓，不阻止平仓；因权益/保证金变化导致已有仓位超过70%时停止新开仓，不自行强平。
  反向信号的平旧仓义务继续；实际平仓后重新检查反向开仓额度，若被拒绝则保持空仓等新信号，不保留旧反手。
- 报价采用对手价限价：买入卖一、卖出买一；无有效报价时不得捏造价格或声称成交。
  每笔新委托从柜台受理时刻起按自然时间累计180秒，午休/闭市不暂停；未成交则撤单。
  确认原单已撤、实际成交核清后，只对剩余数量重新检查最新目标、资金和报价再报单，新委托重新计时。
  闭市等原因暂不能撤单时记录到期取消义务，下一允许时点先核对原单；未核清不能发替代单。
  撤单或成交结果未知时不发替代单，不释放未解释占用，不通过追价绕过资金拒绝。
- 已批准并正在执行的订单撤后跟进，不等于补做曾被资金拒绝的信号；若跟进时资金检查失败，同样终止该次开仓。
  新信号、换月、故障和输入失格继续遵守前述最新目标、取消及恢复边界。

- 收盘截止：按该物理合约日盘/夜盘的权威最终收盘端点（盘中短休、午休不作为此处收盘），剩余时间小于或等于60秒时，
  不再新建/重报开仓单；未成交开仓单发起撤单，该次开仓信号彻底作废，不移至下一时段补开。
  该截止优先于180秒撤后跟进，不能在收盘前一分钟撤完后继续追价。
- Owner明确确认截止仅针对开仓及反手的开仓部分。平仓不因收盘截止而放弃，保留实际旧仓与平仓义务；
  若反手正在平旧仓，截止时仅使后续反向开仓失效，已平后保持空仓，未平继续按原生事实记录。
- 信号作废不等于原委托已撤或已有成交消失。原单撤单/成交未知时仍占用容量、须核对；
  截止后晚到的真实成交必须入账，不伪造空仓，也不因此新增日内强制平仓规则。

自然时间计时与收盘前一分钟放弃开仓已由owner确认；截止是输入/执行时点限制，不是价格止损。
新版 `guiyi_quant.htdy_account_execution` 提供 `start/apply/checkpoint/restore/LocalStore`；
原 `guiyi_quant.htdy_execution` 保留冻结v1政策，原 `opening_allowed` 不能当作新版入口。
`app.htdy_execution.start_account_operational` 绑定现有operational集合，信号复用原公式适配器。

### 资金预留与订单状态机实现边界

- 每个开仓提案在同一事务保存订单、资金/费用预留和风险决定。保证金按有效物理合约、方向保证金率、
  合约乘数及本次对手价用Decimal计算；缺失或过期账户、报价、Session及合约事实时不报单。
- 资金回读明确使用保证金、冻结保证金/费用及逐订单Coverage；只有已证明计入原生冻结的部分才能抵扣本地预留。
  已成交而尚未进入完整资金/持仓回读的变化不能释放后续开仓额度。原生未知状态保持预留。
- 本地提案、原生WORKING、撤单待核、CANCELLED/REJECTED/FILLED及UNKNOWN分别记录。
  原生受理时间只初始化一次；替代单关联前单。终态回调不等于对账完成，必须核对成交及持仓后释放预留。
- 迟到成交保留真实价格、费用和原始时间；无法投影到单品种一手模型的事实单列阻断，不改写为空仓。
  不匹配owner的恢复方向不得创建平仓义务，既有平仓/换月义务继续保留。
- `LocalStore` 使用私有0600 SQLite、BEGIN IMMEDIATE、不可变命令日志及原子投影；重复命令返回零执行提案。
  重开文件强制恢复，允许先保存离线Fill/OrderUpdate，未完成Recover不能执行Tick。
  恢复模式进入日志重放链；原始成交时间保留，处理时钟不倒退。提交结果未知时停止写入，仅查询receipt，不能盲目重发。
- 本地journal可重放核验，不是生产PostgreSQL Ledger，也不声称抵御有权整体改写本地文件的操作者。
  初始账户必须完整核验空仓、无未完成委托、无保证金/费用冻结；重启不重新初始化账户。

报价、合约、Session与Readback均为显式有来源且有有效期的输入；本模块不另建行情resolver。
SUBMIT/CANCEL仍只是已持久化的惰性提案，没有真实发送；未来transport必须实现平今/平昨、原生ID绑定、
受理确认及撤单/成交竞态对账。真实资金生效、第一套环境、自然输入与持续运行分别待验。
