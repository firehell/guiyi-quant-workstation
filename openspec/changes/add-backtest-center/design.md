# 回测中心设计

## 从选策略到复盘

用户从只读策略目录带入策略身份和版本，在回测中心确认配置、提交任务。中心先检查资格与数据覆盖，再将冻结配置交给独立本地进程。进程通过固定适配器调用 RQAlpha Plus。一个成功结果可从工作台打开、逐笔回放，也可作为实验成员参与比较。

| 职责 | 所有者及接口 |
| --- | --- |
| 策略身份、公式、Profile | 策略中心引用领域所有者的版本。适配器把 Plus 的已完成输入交给既有策略内核，将决策按具名执行策略交给引擎。量化计算中心继续提供已有纯计算能力。 |
| 历史行情、合约与交易参数 | Plus 原生读取本地可用数据。中心检查本次请求的覆盖、版本和来源，只保留输入指纹及定位依据；不新增行情同步、镜像或 Market 依赖。 |
| 历史账户 | Plus 处理委托至结算并产生原生成交、权益、分析。归一负责校验成交资格、对账、解释指标口径。研究成交只在所属 Run 内生效。 |
| 配置、任务、证据 | 归一持久化请求、有效配置、状态及结果引用。采用本机有界执行队列和隔离结果存储；沿用应用 API/Web，避免历史扫描阻塞行情或 Paper。 |
| 图表和候选 | Quant Chart 渲染该 Run 的研究图窗与 Marker。候选管理只引用验证证据，变更正式版本或运行阶段仍由 owner 在所属领域决定。 |

## B1 接入边界

仓库锁定的试验依赖是开源 `rqalpha==6.3.0`。P1 的 FU2603 冻结样本可当手算对照，P3/P4 的 MDS 冻结器、盘后 Canonical 凭证及原 profile 是旧试验输入合同。可复用共享决策、原生与建模时间分列、费用核对、原子发布与按 Run 翻页。P3 的正式首日样本仍缺当时可知的 rank1 证据。迁移时保留旧接口和原 Run，新结果使用明确的 Plus 引擎、数据源和研究 profile 身份。现有决策输入来源枚举只有 canonical/observation，接 Plus 时需为研究输入提供真实来源并验证同一公式的前缀等价。退役的通用回测子系统不作为实现入口。

[试验依赖](../../../services/newow-rqalpha/pyproject.toml) · [P1/P3/P4 口径](../../../services/newow-rqalpha/README.md) · [共享决策](../../../packages/quant-core/guiyi_quant/newow/decision_adapter.py) · [结果存储](../../../services/quant-api/app/services/newow_backtest_results.py) · [原读接口](../../../services/quant-api/app/api/newow_backtests.py)

B1 先核实本机 Plus 发行版、版本、授权是否可用、原生接口、已下载数据覆盖及可归档的输入身份。只记录能力和诊断，不记录许可值。优先使用原生入口与分析模块。配置只接受支持的研究参数；固定适配器、限制读写位置、关闭自动更新与外部投递。官方文档的引擎频率为日、分钟、Tick；策略的 5m 等聚合周期另行记录。只开放已证明能生成该策略完整收线、合法执行时钟和对账结果的组合。[米筐本地数据](https://www.ricequant.com/doc/rqalpha-plus/doc/quick-start) · [引擎配置](https://www.ricequant.com/doc/rqalpha-plus/api/config) · [入口函数](https://www.ricequant.com/doc/rqalpha-plus/api/entrypoint)

| 策略目录键 | 首次接入判据 |
| --- | --- |
| `newow_trend` | 优先用 FU 单合约、5m 信号与 1m 执行验证。试验和正式资格分别记录。 |
| `newow_oscillation`、`newow_main_rise` | 分别验证状态机、同 Bar 动作、减仓/清仓政策和共享公式读入；仅开放通过的组合。 |
| `newow_dual_fusion` | 固定趋势、震荡及合成政策版本，基础输出每次只计算一次，核对组合决策。 |
| `htdy_60m` | 原公式含回看重绘，显示观察用途及禁用普通因果回测的原因。 |
| `subing_portfolio_16` | 指向苏冰自身历史回放和共享 Paper 组合，保留原 Run 和账本。 |

每个组合分别检查预热、交易日夜盘与休市、当时可知的主力映射（按主力选约时）、物理合约和交易参数。按同一时间基准保存 Bar 完成、确认/可用、决策生效、委托、建模成交、原生回调与估值时点。例如 09:05 收线于 09:05:02 可用，同 Session 首个合格 1m 开盘最早是 09:06。用原始成交回报核对 tick size、乘数、滑点、保证金、费率、平今/平昨和结算权益；按版本化精度转换为 Decimal，保留引擎原值。限制价、零量及未成交不得生成推定成交。换月后新段重新预热，HOLD 不补开；有仓换月按已验证政策分别处理两份合约，缺政策标记 ROLLOVER_INTERRUPTED；期末持仓单列估值。证据不足以解释的差异阻断正式结果。

## B2 配置与 Run

模板可以编辑。提交时解析默认值，冻结策略目录键、领域公式/Profile、参数、品种与物理合约选择、预热及评价区间、信号/执行周期、初始资金、基准、撮合/费用/滑点/换月政策、引擎和模块版本、策略与适配代码 commit、数据修订与输入摘要。与结果一起保存脱敏后的有效配置。若数据版本只能由路径指认，应计算覆盖本次输入的内容指纹；数据在执行中变化则中止发布。原数据已被替换且无法重现时，显示旧结果和复算限制。

一次显式执行分配一个 run_id。请求幂等键用于吸收客户端重复提交，配置/输入摘要用于判断可比性；显式重跑分配新 run_id 并关联来源。旧 P3/P4 的相同逻辑输入沿用原 run 身份。任务状态为排队、运行、取消中及成功/失败/已取消，另记研究资格。仅在引擎停止且结果未提交时确认取消。终态更新和结果发布互斥；重启后先按 run_id 读回已提交结果和执行状态，提交未知时禁止重复派工。逐笔、权益、报告与成功状态整组发布；乱序、取消与失败保留最后成功结果。进度取实际阶段或引擎回报，日志仅保存脱敏信息。

## B3 工作台与结果

工作台按策略、品种、信号周期、日期和状态筛选，显示总数、运行/成功/失败计数、近期策略、回测、实验与验证任务。保存的配置可再次加载。查询、翻页和图表联动只读已保存结果。详情分为概览、资金曲线、交易明细、风险分析和报告。累计收益、回撤、胜率、盈亏比、收益因子和交易次数均注明来源、扣费及交易配对口径，无法计算时显示原因。可筛选高表现 Run，并同时显示样本类型、回撤和有效交易数。

点击成交时，以 run_id、物理合约、周期、原生成交身份定位同一数据修订的 K 线。按策略事件和实际配对关联展示进出场、方向、持仓区间、价格和净盈亏；部分成交、未平仓分别展示。无法重建对应图窗时保留成交明细并说明缺口，禁止用当前 Market K 线补画。[Quant Chart](../../../packages/quant-chart/README.md)

## B4 参数实验与验证

实验保存比较维度、固定条件、成员 Run、选择标准及失败成员。可比较参数、策略、品种、周期、手续费和滑点。已核实的原生批量能力只在能保留每个成员完整身份和结果时启用，否则分解为有界的独立 Run。比较前显示区间、数据修订、成本、资金、基准及执行政策差异；非实验轴的关键条件不一致时只并列展示，不输出同口径排名。

OOS 在查看测试结果前冻结训练窗口、参数选择规则和不重叠的测试窗口；Walk-forward 每折只用此前训练段选择参数，再对随后测试段运行。每折固定选参截止时点与跨界持仓政策。训练指标只取截止时已可知的成交、费用和估值；跨界未平交易按约定在边界估值或排除，禁止用测试段的平仓结果选参。测试首日记明空仓起步或承接的持仓和权益基线。预热只用可见历史且不计入评价。记录每折边界、选择、样本数、失败与净收益/回撤，重叠测试区间不能重复计入合并曲线。无法证明分割、时序或覆盖时显示证据不足。实验报告引用可追溯的 Run，支持人工复核候选。
