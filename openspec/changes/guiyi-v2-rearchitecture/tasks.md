## Codex 调度建议

- 任务车道：Lane 3，隔离路径涉及行情口径、盘后发布、消费水位与账户隔离。
- 执行入口：Codex App 目标模式。推荐模型：GPT-6.2 Sol。推理强度：中。
- 会话与 Plan：新开开发会话，Plan-then-execute。发送文末 Goal 即批准所列离线计划；集成前新开独立 Review。
- 工作区：从最新 develop 建独立 task branch/worktree，按仓库规则使用 PR 或可核验集成记录。验证、独立 Review 通过后可自动集成 develop。核对远端后只清理本任务已合并且干净的 branch/worktree。
- 人工 Gate：公式、成本与账户合同变更需单独决策；现役停写/切读、正式数据、柜台连接报撤、真实通知、main/tag、Runtime 分别授权。本任务保持 auto_order=false。

## 目标模式开发范围

- [ ] **1. 核对路由与合同。** 阅读 active specs、两账户合同与当前状态。沿启动配置、消费者注册、定时任务、盘后钩子和 Web 路由列出调用链，标明专属与共享依赖、原件/通知/消息定位读者。针对当前前向合同拟定 change delta；存在共享依赖时只摘除隔离 V2 的牛哇参考分发。既有现场服务继续履行其合同。
- [ ] **2. 让盘后发布自动触发。** 从 [P4 消费者](../../../services/quant-api/app/services/newow_backtest_eod.py) 和 [研究任务](../../../services/quant-api/app/services/newow_backtest_job.py) 接正常发布入口。按交易日、成功凭证与输入版本合并受影响系列；覆盖漏领补领、同日无变化与新修订、旧日修订的后续依赖、失败定向重试、重启和乱序。复用[已发布结果存储](../../../services/quant-api/app/services/newow_backtest_results.py)。凭证未就绪零发布，相同版本每系列一个结果；首次失败可解释，有旧成功结果时仍可查询。
- [ ] **3. 核对历史资格与页面。** 三策略六周期按历史顺序重放；抽查已冻结物理合约及 Session、预热、主力、费用和已批准成交时序。保留已知不可发布的情形。让既有主图和面板读取最近成功版本、截至日、完成时间、状态；覆盖首次空、失败、切周期、固定 run 分页和日内报价行情推进。任一读请求都不能触发计算、通知或订单。
- [ ] **4. 证明隔离。** 对隔离 V2 正常入口注入 Tick、全周期收线、无新凭证的定时轮询、Web 刷新，按触发来源断言上述事件导致的牛哇参考内核调用、任务入队、盘中状态提交、通知和交易意图各为零，同时检查行情确实前进。使用相同的账户输入分别在有/无盘后作业时回放，覆盖研究失败、重启及夜盘重叠。按[快期合同](../../../docs/HTDY_SIMNOW_V1.md)核对其回报与未知提交恢复，按[苏冰合同](../../../docs/SUBING_DEVELOPMENT_MODEL.md)核对其原 run、输入次序及模型账目。分别给出处理时延、等待、水位、事件漏重和未验证项。盘后从合格凭证至发布的时长、受影响/完成/失败系列数单列测量。
- [ ] **5. 集成与现场移交。** 独立 Review 检查非预期实时入口、资格与读面、共享依赖和凭证恢复。运行受影响测试、Web/API 回归、OpenSpec 严格校验、secret scan。缺私有样本时记录阻塞的精确验收项，可独立验证的工作继续。提交受测 SHA、集成记录、可回退读取身份、待批准切换清单。生产正式接盘后自动任务、旧消费者停写和 Runtime 生效以现场批准与读回为准。

## 验收证据

| 模块 | 最小可核验证据 |
|---|---|
| Market / Strategy | 同一输入中行情前进、快期/苏冰消费各自需要的事件，行情或页面触发的牛哇参考工作各计数为零 |
| Research | 合格增量发布无人点按钮也能触发；重复/重启仅一次逻辑发布；失败或过期版本不抢成功指针；历史订正只影响依赖系列 |
| Workspace | 实时报价与盘后结果的两个时间、固定 run、缺数状态及旧证据定位；页面操作零新增作业 |
| Trading / Operations | 快期原生事件与苏冰 Paper 事件分列；后台运行时两套基线可复算；报告盘后批次耗时与积压 |
