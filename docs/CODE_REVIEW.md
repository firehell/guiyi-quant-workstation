# 归一量化代码审查指南

外部审查（ChatGPT / 人工）时使用本指南。将 `git diff`、相关文件与本指南一并粘贴到 ChatGPT 对话中，请审查员只输出审查意见，不直接修改仓库。

---

## 1. 审查角色

审查员应关注：

```text
架构审查
回测严谨性审查
量化逻辑审查
风控审查
```

默认只审查，不直接修改文件。输出应包含：

```text
问题清单
风险判断
修改建议
测试建议
是否建议合并
```

---

## 2. 当前项目路线

归一量化 V1 当前路线是：

```text
米筐 RQData
→ 标准 Parquet 数据湖
→ DuckDB 查询 / 周期合成
→ vn.py CTA 回测底座
→ 回测结果标准化
→ PostgreSQL 归档
→ Vue Web 展示
→ K线复盘
→ 信号扫描
→ 人工观察
```

### 关键口径

- V1 主数据源：米筐 RQData。
- V1 回测底座：vn.py / VeighNa CTA BacktestingEngine。
- V1 不使用 VeighNa Studio 作为项目依赖。
- V1 不从零自研完整回测引擎。
- V1 不做实盘。
- V1 不做自动下单。
- V1 不做 tick 级高频回测。
- 天勤 TqSdk 是 V2 模拟 / 半自动实盘候选，不是 V1 必需依赖。
- TuShare 从 V1 移除，后期只作为宏观 / 股票 / 辅助数据候选。
- 旧天勤数据只作为 validation source。
- 交易练习者数据只作为 legacy_reference。
- Web 继续使用 Vue 3 自定义，不使用 vn.py 自带界面。

---

## 3. 审查重点

每次审查必须检查：

### 架构层

1. 是否符合 V1 新路线。
2. 是否仍残留「天勤是 V1 主数据源」的旧口径。
3. 是否仍残留「必须自研完整回测引擎」的旧口径。
4. 是否误把 vn.py 当成最终产品。
5. 是否误依赖 VeighNa Studio GUI。
6. 是否保留归一量化自己的数据仓、任务、报告、复盘、Web 工作台。
7. 是否过度工程化。
8. 是否在 V1 做了不该做的实盘功能。

### 数据层

1. 米筐 RQData 是否作为 V1 主数据源。
2. 外部 SDK 是否被隔离在 data_sources / adapter 层。
3. 回测和前端是否只读本地标准化数据。
4. Parquet 是否保留 raw 和 standard 分层。
5. `market_data_files` 是否记录数据文件索引。
6. `data_quality_reports` 是否记录质量检查。
7. 旧天勤数据是否只作为 validation source。
8. 交易练习者数据是否只作为 legacy_reference。
9. 正式回测是否避免混入旧数据。
10. 凭据是否只从环境变量读取。

### 回测层

1. 是否存在未来函数。
2. 是否存在数据泄露。
3. 信号生成和成交撮合是否错位合理。
4. 是否错误使用当前 K线收盘信号并假设当前收盘成交。
5. 手续费是否计入。
6. 滑点是否计入。
7. 合约乘数是否正确。
8. 保证金占用是否考虑。
9. 最大回撤是否正确。
10. 胜率、盈亏比、连续亏损是否正确。
11. 交易明细是否足够复盘。
12. 参数优化是否提示过拟合风险。
13. vn.py 结果是否被统一转换为归一量化报告格式。

### 风控层

1. 是否适合 10 万级别中小资金账户。
2. 单笔风险是否受控。
3. 最大保证金占用是否受控。
4. 最大持仓数量是否受控。
5. 最大连续亏损是否统计。
6. 最大回撤是否统计。
7. 是否有黑名单品种或策略暂停机制。
8. 是否误允许自动实盘。
9. 是否绕过人工确认。

### Web 层

1. 是否继续使用 Vue 3 + Vite + TypeScript + Naive UI。
2. 是否错误引入 Next.js 或 SSR 复杂度。
3. 是否误使用 vn.py Studio 作为主界面。
4. 页面是否服务于数据、K线、策略、回测、报告、信号、复盘闭环。
5. K线标记是否能对应回测交易明细。
6. 回测报告图表是否能追溯到交易和数据版本。

## 5. 禁止事项

审查时不应建议或推动：

1. 未经确认直接修改仓库文件。
2. 重构整个项目。
3. 删除旧模块。
4. 修改 vn.py 源码。
5. 接入实盘。
6. 写自动下单逻辑。
7. 把账号密码写入代码。
8. 第一版做全自动实盘。
9. 忽略未来函数、数据泄露、过拟合。
10. 把交易练习者数据当正式回测数据。

---

## 6. 推荐审查顺序

大改后优先审查：

```text
1. 文档口径是否统一
2. 数据源边界是否正确
3. vn.py adapter 是否隔离
4. 回测结果是否标准化
5. 苏冰策略是否有未来函数
6. 回测 API 是否阻塞 Web
7. Web 页面是否符合 V1 研究闭环
8. 风控是否在回测和信号层生效
```
