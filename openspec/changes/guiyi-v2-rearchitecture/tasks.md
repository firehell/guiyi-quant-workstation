- 任务车道：Lane 3，隔离路径涉及行情口径、盘后发布、消费水位与账户隔离。

## 目标模式开发范围

- [x] **1. 核对路由与合同。** 已核对隔离 V2 的启动、发布和读面边界，调用链见下方验收记录。既有现场服务继续履行其合同。
- [x] **2. 让盘后发布自动触发。** 从 [P4 消费者](../../../services/quant-api/app/services/newow_backtest_eod.py) 和 [研究任务](../../../services/quant-api/app/services/newow_backtest_job.py) 接正常发布入口。按交易日、成功凭证与输入版本合并受影响系列；覆盖漏领补领、同日无变化与新修订、旧日修订的后续依赖、失败定向重试、重启和乱序。复用[已发布结果存储](../../../services/quant-api/app/services/newow_backtest_results.py)。凭证未就绪零发布，相同版本每系列一个结果；首次失败可解释，有旧成功结果时仍可查询。
- [ ] **3. 核对历史资格与页面。** 三策略六周期按历史顺序重放；抽查已冻结物理合约及 Session、预热、主力、费用和已批准成交时序。保留已知不可发布的情形。让既有主图和面板读取最近成功版本、截至日、完成时间、状态；覆盖首次空、失败、切周期、固定 run 分页和日内报价行情推进。任一读请求都不能触发计算、通知或订单。
- [ ] **4. 证明隔离。** 对隔离 V2 正常入口注入 Tick、全周期收线、无新凭证的定时轮询、Web 刷新，按触发来源断言上述事件导致的牛哇参考内核调用、任务入队、盘中状态提交、通知和交易意图各为零，同时检查行情确实前进。使用相同的账户输入分别在有/无盘后作业时回放，覆盖研究失败、重启及夜盘重叠。按[快期合同](../../../docs/HTDY_SIMNOW_V1.md)核对其回报与未知提交恢复，按[苏冰合同](../../../docs/SUBING_DEVELOPMENT_MODEL.md)核对其原 run、输入次序及模型账目。分别给出处理时延、等待、水位、事件漏重和未验证项。盘后从合格凭证至发布的时长、受影响/完成/失败系列数单列测量。
- [ ] **5. 集成与现场移交。** 独立 Review 检查非预期实时入口、资格与读面、共享依赖和凭证恢复。运行受影响测试、Web/API 回归、OpenSpec 严格校验、secret scan。缺私有样本时记录阻塞的精确验收项，可独立验证的工作继续。提交受测 SHA、集成记录、可回退读取身份、待批准切换清单。生产正式接盘后自动任务、旧消费者停写和 Runtime 生效以现场批准与读回为准。

#### 已关闭的缺陷 · 最新凭证指针不一致被标为完成

- **复现。** 使用有效的最新成功凭证，将其 `FU2605 / 1m / 2026-03` 隔离 Catalog 指针暂时换为同分区另一份已有 Parquet，再运行补领。实测 0.273 秒写入持久完成记录，`series=0, computed=0, failed=[], deferred=0`。恢复原指针并确认凭证再次与 Catalog 一致后，同一凭证补领仍返回 `[]`。
- **影响。** [`_run_one`](../../../services/quant-api/app/services/newow_backtest_eod.py) 把首次 Catalog 校验失败当作空结果，批次收尾 因无延迟项把凭证标为已消费。最新凭证依赖的品种可能漏掉全部系列，页面保留旧结果或空结果，批次却无失败信号。受影响范围为牛哇研究刷新与自动恢复。
- **修复。** Catalog 指针不一致时，只有结果库已有严格更新的同系列发布水位才跳过旧凭证。其余系列记为 `DEFERRED`，保留自动补领资格。消费者重新核对升级前的批次完成记录，已有相同输入的成功 run 按原身份复用。
- **复验。** 临时 PostgreSQL 注入旧版误标完成记录和临时指针不一致，18 个系列均延迟，计算为 0，未写入新版完成记录。恢复指针后同一凭证自动补领，17.693 秒计算 18 个系列，0 失败。API 读回新结果及固定 run，重复轮询零新增。另验已被接替的旧凭证不回退结果，较新的失配凭证不推进水位。定向回归 164 通过，1 项苏冰 PostgreSQL 测试沿用上轮通过证据。针对性独立 Review 无阻断。
