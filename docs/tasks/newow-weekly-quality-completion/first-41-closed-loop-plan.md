## 3. 默认完整周快照

### 3.1 职责和时间

在 Newow 服务层抽取 D1/W1 可共用的快照身份与校验骨架；完成日和完成周的解析策略分别实现。
保留现有 D1 外部接口和行为，用薄适配复用公共部分；W1 增加 completed-snapshot 入口，不另建平行 reader。
Calendar/Session、周归属、Catalog/MDS 仍是时间和输入权威；共享严格 reader 的显式 as_of 行为不放宽。

统一返回以下语义（字段命名实施时随现有 schema 收敛）：

- requested_at：本次打开页面的实际时刻。
- expected_period_end：按权威日历与 Session 应已完成的最近周端点。
- available_period_end：已验证并可展示的周端点。
- snapshot_as_of：所选周最后 Session 结束后一个微秒，遵守既有 strict-before。
- publication/freshness：目标周尚未完成、待发布、已更新、更新失败、过期或不可判定。
- current_context：当前报价/主力/换月的独立状态、时间与来源身份。
- snapshot 身份：product、frequency、cutoff、policy/version、实际所用数据和质量修订证明。

不能把 expected_period_end 写死成自然周五 15:00；节假日短周、跨月/跨年、夜盘和交易所差异走既有 authority。
最近完整周的选择必须基于数据事实，不由哪套策略能 READY、是否盈利或参考交易是否非空决定。
三策略共享同品种同一周截止，各自独立报告预热/中断；所有面板绑定该截止和稳定快照证明。

### 3.2 可展示状态

| 情况 | 默认显示 | 对完成率的处理 |
| --- | --- | --- |
| 本周未完成，上个完整周已验证 | 上个完整周快照，标明截止与本周形成中 | 可正常使用 |
| 新完整周处于可证明的尚未发布阶段 | 展示紧邻前一完整周，明确目标周待更新 | 有限待更新，不能计新周已通过 |
| 发布成功，目标周完整且来源一致 | 原子更新页面请求身份，显示新周结果 | 进入新周验收 |
| 新周已证实缺价或预热不足 | 显示目标周中断/预热状态及可用历史 | 状态正确可验收，不能计策略 READY |
| 维护失败、超出既有维护窗口或状态不可证明 | 显著失败/过期/未验证；已验证旧快照仅作带截止的历史参考 | 自然接续未完成，不能常绿 |
| 历史内部缺口、错身份、损坏或 D1/W1 冲突 | 阻断受影响输入，显示具体原因 | 不通过，不后退掩盖 |
| 当前主力不能证明 | 周快照照其截止展示；当前主力/换月未知，当前持有不可确认 | 不把历史 OPEN 转成当前持有 |

允许待发布的证据来自现有维护目标、阶段、终态和 Catalog/Session 读回；仅看到某条映射缺失，
不足以证明正在发布。默认最多使用紧邻前一完整周，不向前扫描“能成功”的周；前一周也无有效证明则失败。
维护失败后可展示已验证旧快照，但失败/过期优先于 pending 标签，且不选择更早周制造成功。
沿用现有维护截止及允许重试的调度事实，不新造无依据的宽限期、不增加隐含 retry。
显式历史模式与默认模式分开，旧历史搜索不能被当作默认周快照解析器。

### 3.3 当前身份与前端一致性

历史 OPEN 的文案为“截至 X 周仍持有的参考交易”；只有独立当前身份被验证才展示对应当前信息。
周中换月不能使用新主力价格结算旧参考交易；历史回放的换月中断使用截至快照可知的正式映射，
当前身份的变化仅作用于独立当前状态，不改写旧周快照。
缓存依赖包含 Calendar/Session/owner、分区内容与质量修订、周政策版本；同一 as_of 不代表输入未变。
发布/换周期/换策略/换品种时取消旧请求、失效 token/分页，拒绝迟到响应；不允许各面板独自择周。
默认快照沿用现有有界预算（当前解析上限 30 秒），超时如实失败；不无限重试、不靠延长等待掩盖问题。

## 4. 数据与策略可信链

保持 `RQData -> 同源校验 -> Canonical -> Catalog/MainContractMap -> MDS -> Newow reader/service`。
本阶段优先复用已完成输入；重新审核的是实际消费所需 owner 前预热、展示、参考统计和分页窗口。

1. 检查 W1 正常 Bar 的身份、完整预期端点及既有来源证明。来源证明不足时，只读核对对应 D1/质量事实；
   不把“W1 可读”升级为“来源已对账”，也不重复下载已有可信分区。
2. 完整周使用周末交易日 rank1 物理合约的整周来源，不拼每日不同主力，不在查询时临时造替代周线。
3. 已证实 PRICE_UNAVAILABLE 只有在整周全部 D1 端点均有正常或质量解释时，才能形成周中断证明。
   正常周、中断周和未知缺口互斥；同周未知缺日不能被另一已知缺价豁免。
4. 贯通 MDS quality 路径、reader、calculation segment、三策略和 ReferenceTrade；strict 通用查询继续严格。
5. 中断后按有效完整周重新预热；禁止断点前 BUILD 与断点后 CLEAR 配对。断点前 CLOSED 保留，
   中断 OPEN 保留入场与中断原因，不伪造 exit/已完成收益；当前可 READY、历史仍可 PARTIAL。
6. NO_TRADE 只暂停有效观察，不等同于缺价；混合零价周保持现有数值规则，出现语义冲突时提交具体样本决策。
7. 不修改三策略公式、参数、参考价或收益口径；周质量/快照身份单独版本化，D1 Trade ID 不因共享常量改变。

首批出现新缺口仍留在 41 分母，形成精确差量 prepare。生产下载、D1 refresh、Canonical/Catalog 写入
必须明确受影响合约、D1+W1 窗口、已有分区保护、预算、失败恢复并获授权。首批计划不默认需要重新补全部历史。

## 5. 持续更新闭环

复用 18:05 盘后维护与既有 weekly audit，不新增常驻服务或重复 cron。

- 日常维护继续 operational 60 既有职责；首批 41 的消费者只读检查按 W1 发布范围运行。
- 非周末完整日也需验证当前已发布周快照和当前状态分离；仅权威完整周产生后验收新周，不发布未完成周。
- 在现有盘后终态和维护锁释放后运行 `consumer_checks.newow_w1`，分别记录 123 策略组合的各面板结果、
  READY/预热/中断、目标与实际周截止、发布等待/过期、未检项、输入修订和代码身份。
- D1/W1 消费检查共享有界资源调度，不直接复制 D1 的 900 秒预算变成无界双倍；用首批实测确定预算，
  开始和结束检查输入漂移，超时/锁忙/变更标 incomplete，不改写数据维护成功为页面成功，也不触发下载或通知。
- 增加“新主力消费前缀”契约测试：已有 update 的 mapped 日期与整周 D1 context，是否覆盖该策略预热/参考窗口。
  若不足，复用 ContractWarmupPlanner 显式计划受影响 41 品种新 owner 的最小 D1+W1 前缀，归入受控维护阶段，
  不能在页面 GET 或只读 consumer audit 内下载。
- 新 owner 补齐若扩大既有持续授权，实施阶段必须准备可审查的授权范围：41 品种、正式 rank1 引入的物理合约、
  实际 consumer 前缀窗口、D1+W1、每轮请求/字节/耗时上限、维护锁、异常及重试规则。预算由 dry-run 测量，
  本设计不杜撰数值、不自动扩大原自然维护权限。
- 上述受控维护路径未落实时，不能宣称新主力自动接续已完成。周五一次正常也不能替代换月接续证明。
- 来源异常、超预算或提交结果不明时停受影响 mutation，保留已提交事实，按原授权恢复边界处理。
